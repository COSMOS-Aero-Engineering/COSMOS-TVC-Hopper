# 결과 기록과 도움 요청

[학습 안내로 돌아가기](README.md)

담당자는 활동이 끝날 때 아래 다섯 줄과 근거 파일 하나를 남긴다. 화면에 개인정보·토큰·Wi-Fi 비밀번호가 보이면 제거한다. 학생 연락처는 저장소에 넣지 않는다.

```text
내 작업이 프로젝트에서 하는 일:
오늘 연 파일과 실행한 메뉴·명령:
확인한 결과와 근거 파일:
아직 못 한 것과 마지막 오류:
다음 한 단계:
```

예: “IMU 코드의 Build가 SUCCESS였다. Upload와 실물 센서 수신은 아직 하지 않았다. 빌드 로그를 첨부했다. 다음은 USB 단독 업로드 확인이다.” 성공한 단계와 남은 단계를 구분한다.

10분 이상 같은 지점에서 막히면 마지막 오류, 현재 폴더, 실행한 동작, 기대한 결과를 가져온다. ‘안 돼요’만 적는 대신 실패 단계를 찾는다. 설치 오류 / 빌드 오류 / 업로드 오류 / 센서 응답 없음 / 데이터 형식 오류 / 화면 오류를 구분하면 다른 팀원도 이어서 볼 수 있다.

## 산출물별 최소 근거

| 결과 | 같이 남길 것 |
|---|---|
| 실측 | 부품 모델명, 사진의 측정 방향, 값과 단위, 반복 측정값, 미측정 항목 |
| CAD 변경 | 변경 변수, 변경 전후 형상, 실측 근거. 연습 사본인지 정본 반영인지 |
| 회로 검토 | 넷 이름, 논리 핀, 실물 핀 확인 여부, 전압 확인 여부, ERC 결과 |
| 펌웨어 | 대상 프로젝트, Build/Upload/Monitor 중 확인 단계, 로그, 실제 센서 연결 여부 |
| PD·RL | 환경 버전·물리값, 실행 명령, seed, 성공한 검사의 범위. 임시값 표시 |
| 웹 | 합성/실측 구분, 헤더·단위, 변경한 파일, 브라우저 화면과 Console 오류 |

연습 결과는 해당 학습 파일의 사본이나 개인 작업 브랜치에 만든다. 실측 기록은 기존 `cad/measurements.md`, 실험 로그는 `data/`, 기술 설계 변경은 각 설계 정본에 반영한다. 자료실에 실험 결과를 중복해서 저장하지 않는다. PR은 [저장소 협업 규칙](../../README.md#협업-규칙)에 따라 부장·차장이 수동 리뷰한다.
