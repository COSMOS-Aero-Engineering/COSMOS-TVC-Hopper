# 전자·펌웨어: 센서값이 코드와 PC로 오는 길

[학습 안내](../README.md) · [자료실 F01–F11](../resources.md#전자펌웨어)

시우는 보드·센서 단위 동작을 확인하고 재후는 입력·계산·출력을 프로그램으로 연결한다. 오늘 첫 목표는 IMU 스케치의 빌드와 코드 흐름 설명이다. 처음부터 통합 비행 펌웨어를 작성하지 않는다.

![프로그램을 만드는 단계와 실행하는 단계](../images/usb.png)

## 첫 30분

| 순서 | 자료·동작 | 확인할 것 |
|---|---|---|
| 1 | F01의 Hardware Check, F04의 Toolbar 그림 | Build, Upload, Monitor의 차이 |
| 2 | 영상 F05의 10:13–13:56. 설치가 돼 있으면 생략 | VS Code 안에 PlatformIO가 있는가 |
| 3 | `firmware/cosmos/imu_test` 폴더를 VS Code에서 열기 | `platformio.ini`와 `src`가 보이는가 |
| 4 | PlatformIO → Project Tasks → General → Build | 출력 마지막에 SUCCESS인가 |
| 5 | `src/imu_test.ino`의 setup, loop, Serial.print 찾기 | 초기화·입력·출력 세 위치를 설명할 수 있는가 |

CLI가 준비된 사람은 해당 프로젝트 폴더에서 `pio run`을 사용한다. `pio` 명령이 안 잡히면 PlatformIO의 Build 메뉴나 내장 터미널을 쓴다. Build에 성공해도 보드가 인식됐다는 뜻은 아니다. [현재 펌웨어 안내](../../../firmware/cosmos/README.md)를 따른다.

재후는 코드 흐름을 `초기화 → 새 데이터 확인 → 값 읽기 → 출력` 네 칸으로 그린다. 센서 출력 문장의 각 값이 어떤 단위인지 소스와 대조한다. 현재 IMU 출력 각도는 도 단위이고 웹 정식 계약의 자세 필드는 라디안이다. 필드 이름만 맞추고 값의 단위를 바꾸지 않는 실수를 찾는다.

## USB 업로드가 되는 경우의 다음 단계

부장과 USB 단독 상태에서 대상 펌웨어를 확인한 뒤 업로드한다. 실제 PROGRAM 버튼이 손상된 이력이 있으므로 힘으로 누르거나 핀을 임의로 단락하지 않는다. 업로드 로그와 보드의 실제 동작을 함께 기록한다. 포트 목록·LED 점멸만으로 성공했다고 쓰지 않는다.

IMU 연결은 [최신 아비오닉스 문서 §2](../../design/01-avionics-integration-final.md)를 본다. 현재 경로는 SPI다. F02–F03은 **Teensy 4.0** 핀을 읽는 도면이다. F09는 Adafruit BNO085 보드의 핀 역할 설명이므로 우리 GY 모듈의 핀 위치와 전원 사양에 그대로 복사하지 않는다. SDA/AD0라는 실크만 보고 MOSI/MISO라고 단정하지 않는다. 실제 모듈의 모델·데이터시트와 핀맵을 대조한다.

현재 코드의 보고 설정은 50ms다. 실제 로그 간격과 누락을 확인하고 보드를 한 축씩 천천히 돌려 부호를 기록한다. 축을 돌릴 때 움직이지 않는 다른 각도의 변화도 적는다. 이 단계에서는 서보·ESC를 연결해 제어 출력을 내보내지 않는다.

## 그다음 읽을 순서

F06으로 프로젝트·라이브러리 관리를 읽는다. F07로 로딩 과정을 확인한다. F08로 서보 전원과 신호를 구분한 뒤 [논리적 전원 그림](../visuals.md)을 본다. RC의 현재 설계는 FS-iA6B의 PWM 채널 입력이다. iBUS·SBUS 튜토리얼을 현재 코드로 혼용하지 않는다. 수신기 5V 계통과 Teensy 3.3V 입력 사이 레벨 처리는 설계 문서를 따른다.

다음 코드 과제는 RC 한 채널 읽기, 범위·단위·신선도 표시, 입력 끊김 판별이다. 아직 센서·RC·제어·출력을 한 번에 묶지 않는다. 보드가 안 되면 로그 포맷·코드 읽기·빌드를 계속하고 업로드 실패 단계는 따로 남긴다.

## 완료 기준과 막힘

빌드 로그와 세 코드 위치를 보여준다. 실물이 되면 업로드·센서 수신·축 확인을 각각 표시한다. 실제 전압·도통을 검사하지 않았다면 ‘미검사’로 남긴다. 실패 시 프로젝트 경로, 명령 또는 메뉴, 마지막 오류를 가져온다. 라이브러리 버전을 임의로 바꾸지 않는다. [결과 기록 양식](../submission.md)에 확인한 단계만 적는다.
