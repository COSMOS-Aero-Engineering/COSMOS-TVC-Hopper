# 제어·PID: 오차가 어떤 출력으로 바뀌는가

[학습 안내](../README.md) · [자료실 P01–P11](../resources.md#제어pid)

준원은 초보자에게 입력·계산·출력을 먼저 보여주고 이후 기준 제어기를 설계한다. 목표는 제어기가 무엇을 하는지 설명하고 작은 부호 검사를 통과하는 것이다. 최종 PID를 구현했다는 결과와 구분한다.

## 첫 30분

1. [한국어 개념 설명](../concepts.md)의 오차·P·I·D를 읽는다.
2. P03 영상 11:41을 본다. 영어 영상이 어려우면 P10의 서론·PID 강의 목록을 확인하거나 P01의 그림을 함께 설명한다.
3. [동봉 PD 예제](../starter/first_control_exercise.py)를 열고 `error`, `p`, `d`, 출력 제한을 찾는다.
4. 해당 폴더에서 `python first_control_exercise.py`를 실행한다. +10도·-10도·양의 각속도의 결과를 실행 전에 예측한다.
5. 출력과 예측을 대조한다. 마지막 `PASS`는 교육 예제의 부호·감쇠·제한 검사다.

고정 목표 0도, `error=target-angle`이고 각속도 목표도 0인 예제다. +10도일 때 P는 음수다. 기울어지는 방향의 양의 각속도가 더해지면 D도 음수라 복원 요구가 더 커진다. 돌아오는 음의 각속도에서는 D가 양수가 돼 움직임을 완화한다. 숫자는 교육용으로 정했으며 실제 서보 각도·PWM·비행 게인이 아니다.

## 다음: 현재 PD와 믹서 읽기

[기존 baseline PD](../../../sim/connectome/baseline_pd.py)를 열어 상태 6개를 받는 곳과 행동 5개를 내보내는 곳을 찾는다. 자세·각속도에서 roll/pitch/yaw 요구를 만들고 네 베인으로 분배하는 코드를 읽는다. 베인 순서·부호·스로틀 정규화를 표로 적는다. 실제 서보 장착·보정이 확인되지 않은 믹서를 실기에 출력하지 않는다.

현재 PD에는 I 항이 없다. 정식 PID 또는 LQR의 설계와 비교 구조는 [제어 파이프라인](../../design/03-control-pipeline-design.md) §3을 따른다. 이 안내에서 새로운 최종 제어 구조를 확정하지 않는다.

## 수준 있는 PID를 위해 읽을 순서

| 순서 | 자료 | 확인 과제 |
|---|---|---|
| 1 | P09: cascaded loops·discrete systems | 자세 목표 → 각속도 목표 → 토크/베인 요구의 단계와 각 주기를 적음 |
| 2 | P05: derivative·noise | 센서 각속도와 차분 미분 중 어떤 입력을 쓸지, 필터 지연을 어떻게 볼지 적음 |
| 3 | P04, P02: anti-windup | 베인 각도·속도·추력 제한에서 적분 누적과 reset 처리 계획 |
| 4 | P06: tuning guide | 실측·모델·샘플링 확인 전 게인을 확정하지 않는 이유 설명 |
| 5 | P07·P08, P11 | 모델 식별과 튜닝·응답 평가를 다음 설계 검토로 연결 |

필터를 넣으면 노이즈를 줄일 수 있지만 응답 지연도 생긴다. `dt`는 정한 샘플링과 실제 실행 간격을 모두 기록해야 한다. 출력이 제한돼도 I가 계속 커지는 문제를 anti-windup으로 다룬다. 센서 데이터가 오래됐거나 모드가 바뀌었을 때 제어 상태를 어떻게 처리할지도 설계 항목이다. 영상을 본 것으로 이 구현·검사가 완료된 것은 아니다.

## 비교 실험을 먼저 설계하기

PID/LQR과 RL은 같은 초기조건·외란·센서·액추에이터 제한에서 비교한다. 자세 오차, 복원시간, 오버슈트, 정상상태오차, 제어 사용량, 실패 여부를 남긴다. Residual RL이면 순수 RL 직접 비교와 실험 질문이 다르므로 비교군 이름과 출력 결합 방식을 명시한다. 기본 PID가 있다고 실패하지 않는다고 보장하지 않는다.

이번 주 결과는 PD 실행 로그와 현재 baseline의 입력·믹서·출력 설명, 다음 설계 검토 항목이다. 임시 물리값의 시뮬레이션 점수를 실물 호버링 성능으로 쓰지 않는다. [결과 기록 양식](../submission.md)에 구현·검사·미확인 범위를 구분한다.
