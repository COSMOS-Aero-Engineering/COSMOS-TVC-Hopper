# 2주차: 프린트가 없어도 시작하는 활동

[학습 안내](README.md) · [제출 양식](submission.md)

> 2026-10-16 갱신: Teensy 업로드와 IMU 인식은 10/15에 성공했다. 아래 표의 "시우·재후" 첫 과제는 끝났으니, 지금 과제는 [학습 안내의 지금 할 일 표](README.md#지금-할-일-2026-10-16-기준)를 따른다. 나머지 활동 진행 방식(60분·120분 구성)은 그대로 쓴다.

이 문서는 프린트 미발주와 Teensy 업로드 미확인 상태에 맞춘 이번 활동의 운영안이다. 오래된 2주차 계획의 프레임 조립·다리 조립은 여기서 완료 과제로 잡지 않는다. 시간은 활동 배분안이며 설치·다운로드 지연이 생기면 첫 실습을 이어간다.

## 활동 전 부장·차장

저장소와 학습 안내 링크를 공유하고 담당 안내서의 첫 실습을 시연할 수 있게 준비한다. CAD와 회로도를 여는 PC, 웹 실습용 Python과 브라우저, 펌웨어용 VS Code+PlatformIO, 시뮬레이션용 Python+uv를 확인한다. 설치가 안 된 부원은 설치 담당과 짝을 지어 시작한다. 영상이 재생되지 않아도 한국어 설명·그림·동봉 예제로 진행할 수 있게 저장소를 미리 내려받는다.

## 첫 활동 60분

| 시간 | 부장·차장이 할 것 | 부원이 할 것 | 남길 결과 |
|---|---|---|---|
| 0–15분 | concepts.md와 CAD를 열고 팬·베인·센서·보드를 짚는다 | 자기 작업 위치와 부품 역할을 설명한다 | 담당 안내서 선택 |
| 15–25분 | 담당별 첫 실습의 실행 방법과 정상 결과를 보여준다 | 화면·명령·폴더 위치를 따라 찾는다 | 시작 경로 확인 |
| 25–50분 | 막힌 사람의 오류 단계를 확인한다 | 아래 첫 과제 하나를 직접 수행한다 | 파일·표·로그·화면 |
| 50–60분 | 결과와 다음 한 단계를 확인한다 | 결과를 자기 말로 설명한다 | 제출 양식과 근거 파일 |

| 담당 | 첫 과제 | 끝났다고 판단하는 근거 |
|---|---|---|
| 민찬·지훈 | 서보 치수 방향 표시, 두 번 측정, CAD 변수 대응 | 사진 또는 스케치, 단위가 있는 표, 미측정 항목 |
| 민우 | KiCad에서 CS 넷과 핀맵 대조, ERC 실행 | 연결 추적 한 줄, ERC 결과 또는 실행 실패 이유 |
| 시우·재후 | imu_test Build, 입력·초기화·출력 위치 찾기 | 빌드 로그, 코드 위치, Upload와의 차이 설명 |
| 준원 | 교육용 PD 실행, Stage 1 reset/step·상태·행동 찾기 | PASS 로그, 관측·행동 표, sanity 실행 여부 |
| 민지 | 로컬 3D 모형 실행, 슬라이더와 팬 색 수정 | 화면, 바꾼 코드, 모형이 합성임을 설명 |

## 두 번째 활동 120분

| 시간 | 진행 |
|---|---|
| 0–10분 | 지난 결과·오류를 확인하고 같은 지점에서 이어 시작 |
| 10–25분 | 담당 안내서의 다음 자료 한 개를 읽거나 함께 시청 |
| 25–75분 | 아래 조건별 다음 과제 수행 |
| 75–100분 | 다른 담당과 단위·신호·데이터를 대조 |
| 100–120분 | 결과 정리와 짧은 시연, 다음 활동 과제 확정 |

전자·펌웨어는 USB 단독 업로드가 성공하면 확인한 펌웨어 이름·시간·업로드 로그를 기록한다. 이후 부장과 최신 핀맵·실물 모듈의 핀 의미를 대조한 뒤 IMU 단위 시험을 진행한다. 실패하면 장치 인식과 업로드 오류를 기록하고 보드 없는 코드·로그 과제를 계속한다. 버튼·핀을 임의로 단락하는 과제는 주지 않는다.

CAD는 서보 장착 치수와 커넥터 공간까지 확인한다. KiCad는 CS에서 다른 SPI 신호와 전원·접지로 추적 범위를 넓힌다. 계측기가 없으면 실물 전압·도통 검사를 완료했다고 적지 않는다.

제어·RL은 sanity를 통과한 뒤 reward의 항목과 baseline PD의 믹서를 설명한다. 장시간 학습보다 동일 초기조건·seed로 비교하는 계획을 먼저 쓴다. 웹은 합성 CSV의 시간·phi를 읽고 그래프 축과 라디안→도 변환을 설계한다. 현재 starter는 CSV 재생 기능이 없으므로 이를 기존 기능으로 보고하지 않는다.

팀 연결 시간에는 재후·민지가 [정식 CSV 계약](../design/02-web-dashboard-design.md)의 헤더·단위·선택 필드를 대조하고, 시우·준원이 센서 축과 제어 입력의 방향을 대조한다. 자료의 SVG는 신호 구조를 읽는 참고 그림이며 실제 모듈 핀 확인을 생략할 근거가 아니다.

## 이번 활동에서 남길 것

각 담당의 첫 결과 하나, 그 결과가 쓰일 위치 설명, 해결하지 못한 문제 한 줄을 남긴다. 첫 실습이 끝난 담당만 다음 과제를 배정한다. 부장·차장은 결과를 리뷰한 뒤 프로젝트 규칙에 따라 브랜치·PR로 정리한다. 실습마다 잘게 자동 푸시하거나 학생 대신 머지하지 않는다.

프린트 없는 완성 기체 CG 측정, 프레임 조립, 실기 PID 안정화, 온보드 RL 성능 확인은 이번 활동의 완료 기준이 아니다. EDF 시험은 승인·구속·방호·킬스위치 등 기존 조건을 갖춘 별도 시험으로 진행한다.
