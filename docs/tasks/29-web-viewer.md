# #29 CSV 재생 3D 뷰어 (김민지)

## 지금 상태

- 시뮬레이션은 에피소드를 웹 CSV 계약 형식으로 저장한다(`sim/sim_stage1/export_episode.py`, #23).
- 웹 앱 폴더가 없었다. 이번에 `web/`에 **실행되는 뼈대**를 만들었다. 설계 문서(02 §7)대로 Vite + 바닐라 JS + Three.js + PapaParse다.
- 이 위에서 판정 기준을 확인하고 남은 기능을 붙이는 게 이번 일이다.

## 용어

- **Vite:** 웹 코드를 저장하면 브라우저가 바로 새로 고쳐지는 개발 서버이자 빌드 도구.
- **쿼터니언(qw, qx, qy, qz):** 3D 회전을 숫자 4개로 나타내는 방법. 오일러각과 달리 90° 근처에서 망가지지 않는다.
- **Y-up:** Three.js는 위쪽이 +Y다. 우리 기체는 위쪽이 +Z다. 그래서 변환 함수가 필요하다.
- **헤더로 컬럼 찾기:** CSV 첫 줄의 이름으로 칸을 찾는 것. 컬럼 순서가 바뀌어도 안 깨진다.

2026-10-17 확인 (PR #85 리뷰, 서버 Chromium headless):

- `npm run check`가 모두 통과했다. 원래 PR의 베인 코드(세로축 회전)를 넣으면 베인 8개 항목이 실패한다.
- 예전 예제 CSV는 #35(베인 제어력 상수 정정) 전에 만든 파일이라 지금 sim과 달랐다. 예: t=250 ms에서 예전 φ 4.4°, 지금 1.7°. 지금 sim(numpy 2.5.3, gymnasium 1.3.0)으로 다시 만들었고, 두 번 만들어 바이트 단위로 같았다.
- 세 시각 대조표 (판정 기준 2). CSV 값은 Python으로 라디안을 도로 바꿨고, 화면 값은 브라우저 숫자판에서 읽었다.

  | t (ms) | CSV φ, θ, ψ (°) | 화면 φ, θ, ψ (°) |
  |---|---|---|
  | 0 | 4.7, −7.9, −15.8 | 4.7, −7.9, −15.8 |
  | 250 | 1.7, −2.9, −15.5 | 1.7, −2.9, −15.5 |
  | 490 | 0.5, −0.9, −15.5 | 0.5, −0.9, −15.5 |

  화면 숫자는 CSV 값에 180/π를 곱한 것이라 3D 자세는 이 표로 검사하지 못한다. 3D 자세는 `npm run check`의 "쿼터니언 회전 = ZYX 오일러 회전" 항목이 501행 전부를 검사한다.
- 배속: 1×에서 벽시계 1005 ms 동안 t가 980 ms, 0.25×에서 2006 ms 동안 500 ms 갔다.

## 확인 못 한 것

- 실물 서보가 `servo > 0`에서 어느 쪽으로 도는지는 TC-1에서 확인한다. 뷰어는 시뮬레이션의 정의를 따른다. 실물이 반대면 펌웨어 `write_servo()`의 부호를 고친다(01 문서 §1).
- µs 단위 로그는 베인을 움직이지 않는다. µs → 각도 변환은 서보 보정 뒤에 정한다.
- 실물 로그(펌웨어 출력)는 아직 계약 형식이 아니라서 읽을 수 없다. 권재후의 대조표(#28)를 보고 나중에 맞춘다.
- `web/` 폴더 위치는 설계 문서에 정해져 있지 않았다. 부장·차장 확인 필요.
