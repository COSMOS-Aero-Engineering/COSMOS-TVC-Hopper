## 4. 진행 — 금요일 1시간

**목표: 팀 확정 + 모든 팀이 하드웨어 앞에서 시작.**

| 시간 | 내용 |
|---|---|
| 0–20 | 전체 브리핑 — 프로젝트 그림, 8–10주 로드맵, 왜 SolidGeek 논문 기반인지(처음부터 안 만든다), 안전 원칙. 설명회 PPT 재활용 가능 |
| 20–30 | **팀 확정** — 사전 배정 확인, 각자 관심+가능시간. 인원 적으면 겹쳐도 됨(팀당 최소 1명), 팀장 지정 |
| 30–60 | **팀별 착수** ↓ |

- **기구·전자**: 도착 부품 4개 실측 재확인, 포크한 CAD 열어서 바꿀 곳 짚기, 프린트 진행 점검, [`bench-wiring.svg`](bench-wiring.svg) 같이 보기
- **소프트웨어**: 개발환경 전원 확인, CartPole 성공 → Pendulum 시작
- **실험·운영**: 안전 체크리스트 최종, 실험 로그 템플릿, 토요일 추력시험 셋업(배선만, 전원 X)

## 5. 진행 — 토요일 2시간

**목표: 실측 실험 2~3개 완료. 여기서 나온 숫자가 이후 전부(CAD·시뮬·제어)에 쓰인다.**
배선은 [`bench-wiring.svg`](bench-wiring.svg) 참고.

### 실험 A — EDF 정적 추력 곡선 (안전 계획 승인 시)
- 추력 스탠드에 EDF 볼트 고정 → Teensy 시리얼로 스로틀 명령 (10%씩 점증) → 각 지점 **추력·전류** 기록
- **산출물**: T(throttle) 곡선 → TWR 확정, `sim/params.yaml` 추진 파라미터, 실제 최대 추력
- 안전: 스탠드 볼트 고정(손 X), F6 방호판, 보안경, 물리 킬스위치, 지도교사 입회, 첫 스핀업은 최저 스로틀만. 시리얼 스케치에 "2초 입력 없으면 스로틀 0" 페일세이프

### 실험 B — IMU 브링업
- Teensy + BNO085 (I2C) → SolidGeek `BNO080` 드라이버로 쿼터니언/자세 출력
- 손으로 기울여 롤·피치·요 값·부호 확인 → 나중에 제어 부호 정합에 씀. 저전압이라 안전 이슈 없음

### 실험 C — DShot 모터 제어 브링업
- Teensy → ESC로 DShot 스로틀 명령 → EDF 회전 확인 (스탠드 고정, 저스로틀). 실험 A와 같은 셋업에서 이어서

### 병행
- 기구: CAD 모터마운트 수정 마무리, 다음 프린트 큐
- 소프트: 논문 3장(Modelling) — 운동방정식·베인 공력식 읽고 정리

### 세션 완료 기준
- [ ] 팀 3개 + 팀장 확정 / 주간 회의 시간 고정
- [ ] EDF 추력 곡선 데이터 (또는 최소 셋업 완료)
- [ ] IMU 자세 출력 확인 / Teensy가 ESC로 스로틀 제어
- [ ] CAD 모터마운트 실측 반영 / 소프트팀 CartPole+Pendulum 성공

## 7. 부장 리더십 (핵심)

1. **매주 회의 15분**: ①지난주 완료 확인 → ②막힌 것 공유 → ③이번주 배분.
2. **팀장에게 위임, 부장은 팀 간 연결점만** — 기구팀 실측값 → 소프트팀 파라미터, 소프트팀 코드 → 기구팀 배선.
3. **완벽하게 하려다 멈추지 말 것** — 논문·코드가 있으니 그대로 가다 안 맞으면 조정.
4. **안전은 타협 없음** — 지도교사 서명 없이 EDF 전원 안 넣음. 모든 초기 시험 구속 상태.
