## 1. 좌표계 (§3.1)

- **월드 프레임 W**: 관성 고정 좌표계(flat earth).
- **바디 프레임 B**: 기체 무게중심(COM)에 고정, 같이 움직임. **xb·yb축이 베인과 나란히, zb축이
  모터 회전축(=배기 방향)과 나란**하도록 잡음 — 우리 좌표계(설계도 §4, "Z=0 배기면, +Z 위")와
  같은 관례.
- **자세**: Tait-Bryan 각 η=[φ,θ,ψ](roll,pitch,yaw), **ZYX 순서** 회전행렬 R^w_b(ψ,θ,φ) (식 3.2–3.3).
- **바디 각속도 ω_B ↔ 오일러각 변화율 η̇**: 변환행렬 W_η (식 3.4–3.5). **θ=±90°에서 특이점** —
  코드(`hopper_aviary.py`)도 `cos_theta`를 `max(abs(cos_theta), 1e-3)`로 클리핑해서 방어(논문은
  "정상 운용 범위 밖이라 안 다룸"이라고만 하고 넘어감 — 우리 코드가 더 방어적).
- **관성행렬 대각 가정** (식 3.7): 질량이 로컬 축 기준 고르게 분포하면 비대각항(product of inertia)이
  0에 가까워짐 — 논문은 CAD 질량속성 계산으로 검증했다고 함. **우리도 나중에 Onshape/CAD 질량속성으로
  이 가정이 맞는지 확인 필요** (지금은 Jxx=Jyy≈같은 값으로 대칭 가정만 하고 있음, params.yaml 주석 참고).

## 2. 힘·모멘트 구성 (§3.2)

3차원 자유물체도(Fig 3.2): 추력 Ft(모터) + 베인 제어력 F1..F4 + 베인 항력 Fd1..Fd4 + 중력.
**공력(동체 자체의 양력·항력)은 호버 근처에서 무시** — 우리도 동일 가정.

### 2.1 추진력 모델 (§3.2.1)

```
모터 1차계:  ωt(s)/ut(s) = Kt / (τt·s + 1)      (τt = 0.0345s, "충분히 빠름"이라 무시 가능)
추력:        Ft = Kf · ωt²                        (식 3.9)
```

→ 코드 대응: `params.yaml`의 `Kf`. 단, **코드는 실제 RPM(ωt) 대신 `omega_t_equiv = throttle * omega_t_per_throttle`
(throttle 기반 임시 스케일, 상수는 `params.yaml`, #87)을 씀** — 논문처럼 진짜 각속도가 아니다. **실험 A(EDF 추력곡선) 이후엔
DShot에서 읽은 실제 RPM으로 교체해야 논문 식 그대로가 됨.** 모터 1차계(시상수 τt)는 `rotor.enabled`를 켤 때만 쓴다.
켜면 회전자 회전수 Ω가 1차 지연(`params.yaml`의 `rotor.tau`)으로 스로틀을 따라가고, 추력도 이 Ω에서 계산한다
(Ft ∝ Ω², #122). 회전자 반작용·자이로 토크도 같은 Ω를 쓴다(§3 "EDF 회전자 반작용·자이로 항", #86).
끄면(기본) 추력은 지연 없이 스로틀에서 계산한다.

### 2.2 베인 공력 모델 (§3.2.2) — ⚠️ 코드와 논문이 다른 지점

베인은 "대칭 날개(에어포일)"로 취급, 양력(제어력)·항력(손실) 표준식:

```
F_lift = ½ρv²·Cl·A_fin        (3.11)
F_drag = ½ρv²·Cd·A_fin        (3.12)
```

Cl·Cd를 각도 α의 함수로: 대칭 익형이라 ±10° 이내에서 **선형 근사**(Fig 3.6, XFoil 시뮬레이션값 회귀):

```
Cl(α) = CLα·α     Cd(α) = CD0     (식 3.13–3.14)
CLα = 0.008905, CD0 = 0.001054   ← 논문 저자의 "실제 베인" XFoil 회귀값. 우리 베인(25×45×2.5mm)
                                    형상이 다르므로 그대로 쓰면 안 됨 — params.yaml에 이미 PLACEHOLDER로 표시됨
```

**공기 속도 v는 직접 못 재니, 추력 Ft에서 역산** (배기 단면적 A_duct 가정, 식 3.15):

```
v² = Ft / (A_duct·ρ)
```

이걸 대입해서 **최종적으로 베인력을 "모터 추력 Ft에 비례하는 형태"로 정리**(식 3.16–3.17):

```
F_n  = Ft · [ CLα·A_fin / (2·A_duct) ] · α_n   =  Ft · CL · α_n     ← CL은 "뭉쳐진" 상수 (lumped)
F_dn = Ft · [ CD0·A_fin / (2·A_duct) ]          =  Ft · CD
```

**⚠️ 코드 확인 결과 (2026-09-17)**: `hopper_aviary.py`의
```python
F1, F2, F3, F4 = self.CLalpha * Ft * alpha
```
는 `params.yaml`의 `CLalpha`(=논문의 raw `CLα`, 즉 A_fin/A_duct 기하 비율이 **안 곱해진** 값)를
마치 식 3.16의 **뭉쳐진 CL**(=`CLα·A_fin/(2·A_duct)`)인 것처럼 그대로 쓰고 있다. 즉 코드에
`A_fin/(2·A_duct)` 기하 인자가 아예 빠져 있다.

**지금 당장은 문제 없음** — 값 자체가 전부 PLACEHOLDER라 절대 크기가 의미 없고, Stage 1의 목표는
"파이프라인이 도는가"만 확인하는 것이기 때문. **하지만 실험 A 이후 값을 채울 때 둘 중 하나로 명확히
할 것**:
- (A) 실측 추력-베인각-복원모멘트 데이터를 **직접 회귀**해서 "뭉쳐진 CL"을 바로 구한다 → 지금 코드
  구조(`CLalpha`를 뭉쳐진 CL로 취급) 그대로 써도 됨. **다만 `params.yaml`의 변수명 `CLalpha`를
  `CL_lumped`같은 걸로 바꿔서 혼동 방지 권장.**
- (B) 논문처럼 raw `CLα`(에어포일 자체 특성) + `A_fin`(베인 면적, 실측 가능: 25×45mm) + `A_duct`
  (EDF 배기 단면적, `cad/hopper_params.scad`의 `edf_clamp_id` 근처 값으로 근사 가능)를 따로 구해서
  식 3.16대로 곱한다 → 코드에 `A_fin/(2*A_duct)` 항을 추가해야 함.

**결정 (2026-10-16, #27): (B)를 택했다.** 실측 전이라 (A)는 아직 못 한다.

- 확인한 사실: 원저자 MATLAB(`SolidGeek/SingleRotorUAV`의 `MATLAB/NonlinearSimulation/nonlinear_dynamics.m`)은
  `CL = 0.008905`를 `F = Ft·CL·α`에 바로 넣는다. 즉 0.008905는 raw `CLα`가 아니라 **뭉쳐진 CL**이다.
  논문 부록 B.3의 raw 기울기는 `CLα = 0.1081`(1/deg, Joukovsky 익형 XFoil)이다. 본문 §3.2.2의
  "CLα = 0.008905"는 이 둘을 섞어 쓴 표기다.
- 추론(미확인): 0.1081 × A_fin/(2·A_duct) = 0.008905이면 저자 기체의 A_fin/A_duct ≈ 0.165로 그럴듯하다.
  그렇다면 0.008905는 1/deg 단위인데, 저자 펌웨어는 베인각을 rad로 쓴다(`control.cpp`의 `10 * DEG_TO_RAD`).
  저자 기체 치수가 없어서 확인하지 못했다.
- 우리 값: `CL = CLα·A_fin/(2·A_duct)`를 `hopper_aviary.py`의 `vane_lift_gain()`이 계산한다.
  CLα는 2D 6.194/rad에 Helmbold 저종횡비 보정(AR 1.12)을 한 1.637/rad, A_fin = 28 × 25 mm(제트 안에 잠긴 부분),
  A_duct = π·32² mm²(64 mm 공칭). → CL = 0.178/rad. 계산 근거는 `params.yaml` 주석.
- `A_fin`과 `A_duct`는 둘 다 `params.yaml`의 `vane_geometry`에서 계산한다(#98, #117). `A_duct` = π·outer_r²(원 전체,
  꼬리 원뿔 단면을 빼지 않음)다. 배기 내경을 실측하면 `outer_r_mm` 하나만 고친다. `CLα`는 TC-2 실측 회귀로 바꿀 입력이라
  AR에서 계산하지 않는다(#117 결정, 2026-10-18 차장 김준원).
- 상한: 한 축 측력 2·CL·α_max·Ft = 0.062·Ft로, 제트 운동량 상한 Ft·sin(10°) = 0.174·Ft의 36 %다.
  `vane_lift_gain()`은 상한을 넘는 값이 들어오면 ValueError를 낸다.
- 민감도(#27 PR): CL이 이 추정의 0.5배면 PD 합격 기준(중앙값 ≤ 5°)을 겨우 넘지 못한다(5.65°).
  실측 CL이 추정보다 작게 나오면 `domain_rand.cg_offset_mm`부터 다시 볼 것.

## 3. 회전 동역학 (§3.3)

**바디 프레임 토크** (Fig 3.7, l=COM~베인 조인트 거리, r=z축~베인 중심 거리). 원저자 MATLAB의 값도
`l = 0.0947 m`(세로 거리), `r = 0.04 m`다. 우리 `vane_arm_l`은 #27에서 링 반지름 48 mm를
세로 거리 104 mm(`01-avionics-integration-final.md` §8.4)로 고쳤다. `vane_arm_r`은 #34에서 링 반지름 48 mm를
베인 압력중심 반경 18 mm(추정)로 고쳤다. #98부터 r은 `params.yaml`의 `vane_geometry`(잠김 구간 4-32 mm)에서 계산한다:

```
τx = (F1+F3)·l
τy = -(F2+F4)·l
τz = (F1-F2-F3+F4)·r          (식 3.19)
```

**오일러 방정식**(대각 관성 가정 대입, 식 3.22):

```
ω̇x = (1/Jxx)[(F1+F3)l + (Jyy-Jzz)ωy·ωz]
ω̇y = (1/Jyy)[-(F2+F4)l + (Jzz-Jxx)ωx·ωz]
ω̇z = (1/Jzz)[(F1-F2-F3+F4)r + (Jxx-Jyy)ωx·ωy]
```

**월드(오일러각) 변환** — ZYX Tait-Bryan (식 3.24):

```
φ̇ = ωx + ωz·cosφ·tanθ + ωy·sinφ·tanθ
θ̇ = ωy·cosφ - ωz·sinφ
ψ̇ = (ωz·cosφ + ωy·sinφ) / cosθ
```

→ **코드 대응 확인 완료**: `hopper_aviary.py`의 `tau_x/tau_y/tau_z`, `wx_dot/wy_dot/wz_dot`,
`phi_dot/theta_dot/psi_dot` 모두 위 식과 **정확히 일치**(부호 포함). 여기는 논문 그대로 잘 옮겨졌다.

무게중심-추력축 오프셋(`cg_offset_x/y`, `params.yaml`의 `domain_rand.cg_offset_mm`)은 **논문엔 없는
우리 자체 추가**— 조립 오차로 인한 잔류 토크를 근사하려고 넣은 것(τx += cg_offset_y·Ft 등). 타당한
확장이지만 "논문에 없는 부분"이라는 것만 기록.

### EDF 회전자 반작용·자이로 항 (#86, 논문에 없음, 기본 끔)

결론: 회전자 반작용 토크와 회전자 자이로 토크를 `hopper_aviary.py`에 넣었다. `params.yaml`의 `rotor.enabled`가
켜고 끄며, 기본값은 끔이다(2026-10-18 차장 김준원 결정, #86 댓글). 상수는 공개 자료와 가정으로 잡은 추정값이고 실측값이 아니다.

**왜 논문에 없나.** Jacobsen은 반대로 도는 모터 2개를 써서 모터 토크의 합이 0이라고 보고 뺐다(§3.2, 원문 22쪽).
같은 논문 §2.2.1은 EDF가 회전축 둘레로 큰 회전 모멘트를 만들고, EDF로는 반대로 도는 짝을 만들 수 없다고 적었다.
우리는 EDF 1개라 이 토크가 상쇄되지 않는다.

**식.** 회전자(관성 I_r, 바디 기준 각속도 Ω, 축 = 바디 z)를 품은 강체의 각운동량은 L = J·ω + h, h = s·I_r·Ω·e_z다.
J는 회전자를 포함한 기체 전체 관성이고, s는 `rotor.spin_dir`(±1)이다. 바디 프레임에서 dL/dt + ω × L = τ를 정리하면:

```
J·ω̇ = τ − ω × (J·ω) − ω × h − dh/dt
  반작용  −dh/dt = (0, 0, −s·I_r·Ω̇)               스로틀을 바꿀 때만 생긴다
  자이로  −ω × h = (−s·I_r·Ω·ωy, +s·I_r·Ω·ωx, 0)   기체가 롤·피치로 돌 때 생긴다
```

- 반작용 휠 위성 식과 같은 꼴이다: J·ω̇ = −ω × (J·ω + h_w) + u + d, ḣ_w = −u
  ([Shahraki & Lessard 2024, arXiv:2409.19936](https://arxiv.org/html/2409.19936v2) 식 4b·4c). u = −ḣ_w를 넣으면 위 식이 된다.
- [tvc-retro-propulsion](https://github.com/Jacob19999/tvc-retro-propulsion)(MIT, 커밋 971e24d)의
  `simulation/isaac/tvc_env/dynamics/rotor_reaction.py`도 같은 항(스풀 반작용 −I·dΩ/dt, 자이로 −ω × H)을 바디 토크로 더한다.
- [PX4 PR #21489](https://github.com/PX4/PX4-Autopilot/pull/21489)(Bresciani, 단일 덕티드팬 기체, 머지 안 됨)는 레이트 제어기에서
  `rate.cross(Vector3f(0, 0, H))`로 이 자이로 토크를 상쇄한다. H는 회전수 합 × `MC_PRECESS_GAIN`이다.
- 부호: +Z = 위(흡기 쪽, AGENTS.md §프로젝트 한눈에의 좌표계). s = +1이면 회전자 각속도가 +Z를 향한다.
  흡기 쪽에서 내려다보면 반시계다. 이때 스로틀을 올리면 기체는 −ψ 방향으로 돈다.
  64 mm EDF는 CW 판과 CCW 판이 따로 팔린다(예: [AEORC XF6408 CW](https://probots.co.in/aeorc-xf6408-64mm-edf-4000kv-cw-brushless.html)·[CCW](https://probots.co.in/aeorc-xf6408-64mm-edf-4000kv-ccw-brushless.html) 판매 목록).
  산 EDF의 방향은 TC-0에서 확인한다.

**넣지 않은 것: 정상 상태 공력 반작용.** 팬이 공기를 돌리는 토크(Q = k_Q·Ω²)는 EDF 안의 고정 날개(스테이터)가
흐름의 회전을 되돌리면서 상쇄한다고 가정했다. tvc-retro-propulsion도 `edf_90mm.yaml`에서 `k_Q: 0.0`으로 두고
"stator/duct cancels steady rotor reaction; replace with measured residual yaw torque"라고 적었다.
스테이터는 공기에만 작용하므로 회전자 자신의 각운동량 변화(dh/dt)와 자이로 항은 상쇄하지 못한다.
남는 정상 요 토크는 실측으로 확인한다(#119).

**회전수 모델(가정).** Ω는 목표 `omega_max`·throttle을 시상수 `tau`의 1차 지연으로 따라간다.
같은 꼴의 모델: Jacobsen 식 3.8(1차계, 부록 A.4 τt = 0.0345 s),
tvc-retro-propulsion `propulsion_edf.py`(ω_target = throttle·ω_max, 1차 지연).
- 에피소드 첫 스텝에서는 회전자가 이미 그 스로틀로 돌고 있었다고 둔다(가정). 구속 스탠드 시험은 팬을 돌린 상태에서
  자세 교란을 준다. 그래서 첫 스텝의 반작용은 0이다.
- 회전수는 관측(obs)에 없다. 스위치를 켜면 정책이 못 보는 상태가 하나 생긴다(시상수 0.05 s). 실물에서 받으려면 ESC 텔레메트리가
  필요해서 지금은 넣지 않는다(#186 결정, 아래 "스로틀 변화율 제한").

**추력과 회전수(#122 결정, 2026-10-18 차장 김준원).** 스위치를 켜면 추력도 지연된 회전수에서 계산한다.
추력용 스위치를 따로 두지 않는다.

```
u  = Ω / omega_max                       유효 스로틀(0-1). 회전수가 다 따라가면 스로틀과 같다
Ft = Kf · (u · omega_t_per_throttle)²    끈 경우의 식에서 throttle 자리에 u를 넣었다
```

- 물리로는 추력도 Ft ∝ Ω²라서 회전수와 같은 지연을 가진다(논문 식 3.8-3.9). arXiv 2504.07694는 추력 응답 지연을
  넣은 것을 실물 이식의 핵심으로 적었다(`rl-open-source-survey.md` §4).
- 추력은 스텝 끝 회전수 Ω1로 계산한다(`hopper_aviary.py`의 `_advance_rotor()`). 그래서 tau = 0이면 추력이 스위치를 끈
  경우와 같다. 에피소드 첫 스텝은 회전자가 이미 돌고 있다고 두므로 이때도 같다.
- 스위치를 끄면 추력은 지금처럼 스로틀에서 바로 계산한다. 환경 출력은 #122 전과 비트 단위로 같다
  (seed 0-199, 무작위 행동·PD·스로틀 계단 PD 롤아웃의 SHA-256 비교, #122 PR).
- `yaw_check.py` 2번 다: 스로틀 1.0 → 호버 스로틀 0.853 계단 뒤 5번째 스텝(명목 tau의 1배)에 롤 명령을 주고 Δω로 추력을 잰다.
  해석해 u = 0.907에서 Δωx = 0.1053 rad/s다. 지연 없는 추력(u = 0.853)이면 0.0932 rad/s라서 검사가 실패한다.
  #204 전에는 계단 목표가 0.75였다(u = 0.842, Δωx 0.0907, 지연 없으면 0.0720 rad/s). 계단 목표는 아래 "호버 스로틀"에 있다.

**`omega_t_per_throttle`과 `rotor.omega_max`의 관계.**
- `omega_t_per_throttle`(3000)은 임의 단위다. `Kf`와 짝을 이뤄 최대 추력만 정한다: Kf·3000² = 9.9 N.
- `rotor.omega_max`(3800 rad/s)는 회전수 추정값이다. 회전자 각운동량 h = s·I_r·Ω(반작용·자이로)에만 들어간다.
- 추력 식은 u = Ω/omega_max만 쓴다. 목표 회전수가 omega_max·throttle이라 u는 omega_max와 상관없다.
  그래서 omega_max를 바꿔도 추력은 바뀌지 않는다.
- 두 상수를 함께 쓰면 회전수 기반 추력 계수가 나온다: Ft = Kf_Ω·Ω²,
  Kf_Ω = Kf·(omega_t_per_throttle/omega_max)² = 1.1e-6 × (3000/3800)² = 6.86e-7 N/(rad/s)².
  두 PLACEHOLDER에서 나온 값이라 실측값이 아니다. 실험 A에서 추력과 회전수를 함께 재면 이 값과 비교한다.

**적분.** 자이로 항만 사다리꼴(중점) 규칙으로 적분한다. 나머지 항은 지금처럼 전진 오일러다.
- 전진 오일러는 자이로 항이 있으면 스텝마다 회전 에너지를 (1 + (h·dt/J)²)배 키운다. 명목값에서 5초 동안 자유 세차를
  적분하면 |ω|가 4.22배가 되는 것을 확인했다. 사다리꼴 규칙은 같은 조건에서 |ω|를 0.4999998/0.5로 지켰다.
  tvc-retro-propulsion `rotor_reaction.py`의 `compute_midpoint_gyroscopic_torque()`도 같은 이유로 중점 규칙을 쓴다.
- 스위치를 끄면 환경 출력은 main과 비트 단위로 같다(50 seed, 무작위 행동 6542 스텝 비교, #86 PR).

**랜덤화(#121 결정, 2026-10-18 차장 김준원).** 랜덤화를 켜면 `reset()`이 에피소드마다 위 범위에서 세 상수를 뽑는다.
범위는 `params.yaml`의 `domain_rand.rotor_*_range`에 있고, 분포는 `hopper_aviary.py`의 `ROTOR_RAND_LOG`에 있다.
- 분포: 범위가 넓은 척도 값(관성 7배, 시상수 5배)은 로그 균등으로, 좁은 값(`omega_max` 1.29배)은 균등으로 뽑는다.
  로그 균등은 비율마다 같은 확률을 준다. 관성이 명목 1e-5 아래일 확률은 36 %다(균등이면 17 %). 시상수가 0.06 s 위일
  확률은 57 %다(균등이면 75 %). Peng et al. 2018([arXiv:1710.06537](https://arxiv.org/abs/1710.06537) 표 I)은 질량·감쇠·마찰·게인을
  로그로, 나머지를 균등으로 뽑았다. OpenAI 2018([arXiv:1808.00177](https://arxiv.org/abs/1808.00177) 표 1)도 관절 감쇠와
  액추에이터 게인을 loguniform으로 뽑았다. 로그 균등 밀도는 f(x) = 1/(x·ln(b/a))다([SciPy `loguniform`](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.loguniform.html)).
- seed 재현: 세 이름을 `EPISODE_STREAMS`에 더하고 `self._rng(이름)`에서 뽑는다(#98). 다른 값(Jxx-Jzz, l, r, Kf, 무게중심 오프셋)과
  초기 자세의 seed 0-199 표본은 #121 전과 비트 단위로 같다. 스위치를 끈 환경 출력도 같다(#121 PR).
- `omega_max`를 바꿔도 추력은 그대로다(위 "추력과 회전수"). `omega_max` 랜덤화는 회전자 각운동량만 바꾼다.
- `yaw_check.py` 1·2번 손계산은 랜덤화를 끄므로 명목값을 쓴다. 3번 요 PD는 seed마다 뽑은 값으로 돈다.

I_r 계산. 회전하는 부분은 임펠러와 아웃러너 모터의 캔(자석 포함)이다.
- 임펠러: [HobbyKing 64 mm 12날 EDF](https://hobbyking.com/blade-high-performance-64mm-edf-12-blades.html)는 유닛 전체가
  43 g이다(흡기 립·스피너 포함). 회전자만의 질량은 공개 자료를 찾지 못해서 8-20 g로 가정했다.
  I = k·m·R², R = 32 mm, k = 0.25-0.6(허브 쪽 질량이 클수록 작다) → 2.0e-6 - 1.2e-5. 중간값(12 g, k = 0.4)은 4.9e-6이다.
- 모터 캔: [Freewing 2836-3300KV](https://motionrc.com/products/freewing-2836-3300kv-brushless-outrunner-motor-mo028363)
  (64 mm 12날 EDF용 4S 아웃러너)는 85 g, 지름 28 mm다. 회전하는 캔과 자석을 그중 25-45 g로, 질량 반경 11-13 mm의 얇은
  원통으로 가정했다. I = m·r² → 3.0e-6 - 7.6e-6. 중간값(35 g, 12 mm)은 5.0e-6이다.
- 합: 5.0e-6 - 2.0e-5, 중간값 9.9e-6 → 명목값 1.0e-5.
- 교차 확인: tvc-retro-propulsion의 90 mm EDF 추정값 2e-4 kg·m²(`edf_90mm.yaml`)를 닮은꼴 비 (64/90)⁵로 줄이면
  3.6e-5다. 그래서 범위 위쪽을 3.5e-5까지 넓혔다.

`omega_max` 계산. 부하 회전수 ≈ KV × 배터리 전압 × 부하율이다.
- KV 후보: BOM 후보 Freewing 64 V2 3100KV(`BOM.md` A1), 구매 시트 3500KV(`docs/execution/procurement-review.md` A1),
  HobbyKing 64 mm 12날 팬의 4S 권장 2800KV. 4S 부하 전압은 14.0-14.8 V, 부하율은 0.75-0.85로 가정했다.
- 명목값: 3100 × 14.8 × 0.8 = 36,700 rpm(3843 rad/s) → 3800 rad/s.
- 아래쪽: 2800 × 14.0 × 0.75 = 29,400 rpm(3079 rad/s) → 3100 rad/s.
- 위쪽: HobbyKing 64 mm 12날 팬의 최대 회전수 38,000 rpm(3979 rad/s)에서 자른다 → 4000 rad/s.
  3500KV × 14.8 V × 0.85 = 44,000 rpm은 이 한도를 넘어서 쓰지 않았다.

**호버 스로틀(#204 결정, 2026-10-19 AI 결정, 차장 위임).** 결론: `yaw_check.py`의 계단 목표는 시뮬레이션 호버 스로틀이다.
`hopper_aviary.py`의 `hover_throttle()`이 `params.yaml`의 `mass`·`Kf`·`omega_t_per_throttle`에서 계산한다. `altitude_check.py`도 같은 함수를 쓴다.

```
u_h = sqrt(mass · g / (Kf · omega_t_per_throttle²))    추력 식 Ft = Kf·(u·omega_t_per_throttle)²에서 Ft = mass·g를 푼 값
    = sqrt(0.735 × 9.81 / 9.9) = 0.853                  명목값
```

- #204 전에는 `yaw_check.py`에 `THROTTLE_HOVER = 0.75`를 따로 적었다. 01 문서 §8.1의 AUW 735 g, 정적 추력 1300 gf에서
  √(735/1300)로 구한 값이다. 시뮬레이션의 최대 추력은 Kf·3000² = 9.9 N(1009 gf)이라 0.75에서는 추력이 무게의 0.77배였다.
  그래서 시나리오 B는 호버가 아닌 스로틀로 계단을 줬다.
- 두 값 모두 추정값이다. 실험 A로 Kf가 바뀌면 `params.yaml`만 고친다. 호버 스로틀은 그 값에서 다시 계산된다.
- 고른 이유: 출처를 하나로 두면 Kf나 질량을 고칠 때 계단 목표가 조용히 어긋나지 않는다. ArduPilot도 호버 스로틀을
  추력 0-1 값 하나(`MOT_THST_HOVER`)로 두고 비행 중 학습한다(`MOT_HOVER_LEARN`).
- 1번 토크 손계산과 3번 A·끔 판정 줄은 계단 목표를 쓰지 않아서 결과가 같다. 2번 가·다·라와 3번 B 줄의 숫자가 바뀌었다.
  `altitude_check.py` 출력은 #204 전과 글자 단위로 같다.

### 베인 서보 동특성 (#161, 논문에 없음, 기본 끔)

결론: 베인 서보의 데드밴드·1차 지연·속도 제한을 `hopper_aviary.py`의 `_advance_servo()`에 넣었다. `params.yaml`의 `servo.enabled`가
켜고 끄며, 기본값은 끔이다(2026-10-19 AI 결정, 차장 위임, #161 댓글). 끄면 베인각은 행동을 받은 스텝에 바로 명령각이 된다.

**모델.** [tvc-retro-propulsion](https://github.com/Jacob19999/tvc-retro-propulsion)(MIT, 커밋 971e24d)의
`simulation/isaac/tvc_env/dynamics/actuator_servo.py`와 같은 꼴이다. 베인마다 한 스텝(dt)에:

```
e  = α_cmd − α0;  |e| < deadband이면 목표 = α0(움직이지 않음), 아니면 목표 = α_cmd   데드밴드는 오차에 건다
α1 = 목표 + (α0 − 목표)·e^(−dt/tau)                                                   1차 지연(스텝 동안 명령 일정, 해석해)
α1 = clip(α1, α0 − rate_max·dt, α0 + rate_max·dt)                                     속도 제한
```

- 참고 구현은 1차 지연을 전진 오일러(α0 + dt·e/tau)로 적분한다. 우리는 회전자 회전수와 같은 해석해를 쓴다. dt가 tau에 가까워도 명령각을 넘지 않는다.
- 힘은 스텝 끝 베인각 α1로 계산한다(회전자의 Ω1과 같다). 에피소드 시작 때 베인은 중립(0)이다.
- 데드밴드 때문에 베인은 명령보다 최대 데드밴드만큼 모자란 곳에서 멈춘다. 오차가 데드밴드 안에 들어오는 스텝에 멈추기 때문이다.

**상수(전부 실측 아님).**

| 상수 | 값 | 근거 |
|---|---|---|
| `servo.rate_max_dps` | 600°/s | [TowerPro MG90S](https://www.towerpro.com.tw/product/mg90s-3/) 0.10 s/60°(4.8 V, 무부하). [Waveshare MG90S](https://www.pishop.us/product/mg90s-micro-servo-metal-gear/)는 0.11 s/60° |
| `servo.deadband_deg` | 0.45° | Waveshare dead band width 5 µs × 0.09°/µs(펄스 1000 µs당 90° 가정). TowerPro는 1 µs(0.09°). 우리 서보가 정품인지 몰라서 큰 쪽을 쓴다 |
| `servo.tau` | 0.05 s | 데이터시트에 없다. tvc-retro-propulsion 추정값(MG996R)과 같고 `03-control-pipeline-design.md` §5의 20-60 ms 안이다 |

- tau 0.05 s에서는 1차 지연의 최대 속도 2·alpha_max/tau = 400°/s가 속도 상한 600°/s보다 작다. 그래서 명목값에서는 속도 제한이 걸리지 않는다.
- 상수는 랜덤화하지 않는다. 켤 때 실측 범위로 랜덤화할지 같이 정한다.

**기본값을 끔으로 둔 이유.** tau는 데이터시트 값이 아니고, 서보 실측(TC-2, 실험 A)은 #161의 제외 범위다. 회전자 항(#86)도 실측 전에는 끔으로 두었다.
켜면 실제 베인각이 정책이 못 보는 상태가 된다. MG90S는 위치 피드백이 없어서 실물에서도 재지 못하므로 관측에 넣지 않았다(#186과 같은 기준).
켤 때 직전 행동을 관측에 넣을지 같이 정한다(legged_gym이 구동기 지연을 다루는 방법, #186 댓글).

  그래서 실측 tau가 0.15 s 이상이면 요 PD 게인(kp=8, kd=2)을 다시 정해야 한다.
- `yaw_check.py` 2번 마.: 1차 지연 해석해(상대오차 3.6e-16), 데드밴드(안쪽 명령에 베인 0°, 바깥 명령에 움직임), 속도 제한(tau 0에서 경사 차이 2.8e-17 rad)을
  손계산과 비교한다. 이 검사는 스위치와 상관없이 서보 모델을 켜고 돈다.

## 4. 병진 동역학 (§3.4) — Stage 1엔 미사용, Stage 2용 참고

바디프레임(식 3.29) → 월드프레임(식 3.31) 가속도/속도 식. **위치(x,y,z)까지 제어하는 건 Stage 2**
(위치 구속 M1을 풀고 자유비행 갈 때) — Stage 1(`HopperAttitudeEnv`)은 자세(φ,θ,ψ,ωx,ωy,ωz) 6개
상태만 쓰고 위치·속도는 없음. Stage 2 만들 때 이 절을 그대로 가져다 쓰면 됨.

## 5. 선형화 · 상태공간 (§3.5) — 논문은 LQR용, 우리는 지금 안 씀

논문은 호버점(φ=θ=0, Ft=mg)에서 야코비안 선형화해 12차원 상태공간 모델(식 3.41–3.43)을 만들고
Ch.4에서 LQR 게인을 설계한다. **우리 Stage 1은 이 선형화를 안 거치고 비선형 방정식을 numpy로 직접
적분**(오일러 적분, dt=0.01s) — RL(PPO)은 선형 모델이 필요 없어서다. 이 절은:
- 나중에 **LQR을 PID 대신/추가로 baseline에 넣고 싶으면** 그때 필요 (`03-control-pipeline-design.md` §3 PID vs RL 비교 구조
  참고 — 지금은 PID 또는 LQR 둘 다 "baseline" 후보로 열어둠).
- 제어 입력 벡터 정의 `u=[α1,α2,α3,α4,ωt]`(식 3.37)는 **우리 action space(5차원, `hopper_aviary.py`)와
  구조가 동일** — 단 우리는 ωt 대신 정규화된 throttle을 씀.
