# CAD 검사와 질량 시나리오 (2026-10-20)

이 보고서는 계산 결과다. 제조·비행 승인이나 실물 체결 증거가 아니다. #219의 실제 MG90S·혼·출력물 측정, #118의 배기 내경·허브 실측이 남아 있다.

## 바뀐 배치 (#222)

전자부 선반에서 UBEC와 무게추 후보가 0.026684 cm3 겹쳤다. 수신기와 선반도 0.000100 cm3 겹쳤다. UBEC를 반경 70 mm로 옮겨 무게추와 1.5 mm 설계 간격을 뒀다. 수신기를 기판 바깥쪽, Teensy와 IMU를 안쪽에 나눠 놓고 수신기 바닥을 기판 윗면에서 0.5 mm 띄웠다. 이 간격을 유지할 실제 절연·고정 방법은 확인 필요다.

수신기는 FS-iA6B 제조사 페이지의 26.2×47×15 mm, 10 g 공칭값이다. 실제 구매한 수신기의 모델·외형·질량은 확인하지 않았다. 만능기판·헤더·레벨시프터는 높이 4 mm의 보수적 간섭 외피로 통일했다. 수신기·Teensy·IMU는 이 외피에서 0.5 mm 띄웠다. 질량표·showcase·간섭 검사에 같은 배치 후보를 사용했다. 서보 외형도 별도 축소 모형 대신 CAD의 `servo_blocks()`를 검사한다. 이 외형은 아직 실측하지 않은 가정이다.

## 슬라이서 질량 (#223)

PrusaSlicer 2.9.6 공식 릴리스의 Windows 배포판으로 8개 부품군을 실제 계산했다. 다운로드 SHA256은 `5aaf22e42f95accecfa122d23a835911f289ecc2ff606db3e83d637ddcc0a209`이다. 프로파일은 노즐 0.4 mm, 레이어 0.2 mm, 외벽 4줄, 상하면 각각 6층, gyroid 인필 40%, 필라멘트 1.75 mm, PETG 밀도 1.27 g/cm3 가정이다.

| 부품군 | 슬라이서 질량 (g) |
|---|---:|
| 상판 | 31.39 |
| 베인링 | 153.57 |
| 베인 4개 | 13.54 |
| EDF 클램프 | 19.22 |
| 배터리 선반 | 21.64 |
| 전자부 선반 | 22.28 |
| ESC 브래킷 | 8.83 |
| 커플러 4개, 기본 규격만 | 9.28 |
| 합계 | 279.75 |

커플러 여유 규격을 중복 합산하지 않았다. EVA 발 범퍼와 구매품은 원본 질량표 가정을 유지했다. [slice-reference.json](slice-reference.json)에 버전·프로파일·입력 STL 해시와 슬라이서 경고를 보존했다. 프로파일·원본 질량표의 텍스트 해시는 줄바꿈을 LF로 통일해 계산하며 STL은 원본 바이트를 쓴다. [parts-reference.csv](parts-reference.csv)는 이 질량만 대입한 독립 계산표다. 원본 `cad/cg/parts.csv`를 측정값인 것처럼 덮지 않는다.

| 시나리오 | 전체 질량 | CG x/y/z (mm) | 토크 팔 z+36 (mm) | 사양 추력 기준 TWR |
|---|---:|---|---:|---:|
| 현재 인필만 계산한 하한 가정 | 775.97 g | +0.17 / -0.40 / 84.52 | 120.52 | 1.675 |
| 위 슬라이서 프로파일 | 930.24 g | +0.14 / -0.68 / 75.82 | 111.82 | 1.397 |

정적 추력 12.75 N은 사양 가정이며 실측이 아니다. 슬라이서 시나리오에서도 CG z가 기존 목표 60–75 mm를 약 0.82 mm 벗어난다. 현재 sim의 l=104 mm를 새 값으로 자동 교체하지 않는다. 실제 질량·조립 위치 확인 뒤 #219와 #26에서 제어 상수와 트림량을 결정한다.

목표 범위 밖일 때의 계산상 조정안: 다른 질량과 위치가 같다면 159.5 g 배터리 중심을 5 mm 내리면 CG z는 약 74.96 mm가 된다. 이는 배터리 선반의 높이를 분리 조정해야 하는 설계안이며 현재 CAD에는 적용하지 않았다. 실제 출력물 질량·배선·체결을 확인한 뒤 #219와 #26에서 선택하고 전체 간섭 검사를 다시 해야 한다. 지금 목표에 맞추려고 추정값을 실측값처럼 바꾸지 않는다.

### 재현

먼저 최신 CAD에서 STL 10종을 만든다. 두 번째 명령의 출력 폴더는 새 폴더여야 한다.

```powershell
python cad/tools/export_print_parts.py --out cad/print_parts
python cad/tools/slice_reference.py --slicer <PrusaSlicer-2.9.6의 실행파일> --stls cad/print_parts --out <새 로컬 폴더>
python cad/cg/cg_estimate.py <새 로컬 폴더>/parts-reference.csv
```

모든 STL의 조립 방향을 그대로 사용했고 서포트는 껐다. 링·베인·클램프·커플러 등에서 공중에 뜬 부분, 브리지, 접착·느슨한 압출 관련 경고가 나왔다. 출력 방향·장비·서포트·업체 필라멘트가 확정되지 않았으므로 이 G-code는 실제 출력에 사용하지 않는다. 최종 부품 질량과 강도도 보증하지 않는다. 슬라이서의 경로 폭·레이어 양자화 때문에 일부 얇은 부품의 계산 질량은 연속 실체 부피×밀도보다 클 수 있다. 두 수치를 엄밀한 상하한으로 해석하지 않는다.

## 간섭 검사 (#220)

OpenSCAD 2021.01 전체 실행 exit 0. 당시 부품·편향 상태 25개, 비교 297쌍 중 경계 상자가 겹친 34쌍을 정밀 검사했다. 두께 없는 면·선 접촉 5쌍, 허용값 0.001 cm3를 넘는 부피 간섭 0건이다. 빈 STL은 접촉의 근거로 쓰지 않는다. OFF 재출력의 모든 연결 조각이 두께 없는 축 정렬 면·선인 경우에만 접촉으로 분류하며, 실제 부피·알 수 없는 경고·렌더 오류는 실패한다.

교차 리뷰 뒤 만능기판 조립 외피, 수신기, Teensy, IMU를 고치고 킬스위치를 검사에 추가했다. 현재 상태는 26개이고 전체 비교 범위는 322쌍이다. 이전 전체 실행과 삼각형 단위로 대조한 결과, 바뀐 형상은 위 5개뿐이다. 이 5개가 포함된 115쌍을 다시 선별했으며 경계 상자가 겹친 `avionics_shelf`/`perfboard` 1쌍을 현재 형상으로 렌더했다. 교집합은 비어 있었다. 따라서 이전 전체 실행의 나머지 207쌍과 이번 집중 검사 115쌍을 합쳐 현재 322쌍을 확인했다. 이 결합 검증은 실제 체결·배선 여유를 확인한 결과가 아니다.

현재 형상의 showcase도 실제 재생성했다. [완성 모습](../../renders/showcase.png)은 발표용 외형 자료이며 조립 순서·강도·배선 검증을 대신하지 않는다.
