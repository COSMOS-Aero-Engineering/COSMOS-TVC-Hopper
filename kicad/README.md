# kicad/ — 회로도(스키매틱) 캡처

## 현재 상태 (2026-10-17)

**스키매틱은 사람이 그린 파일이 아니라 생성물이다** — `cosmos-avionics/cosmos-avionics.kicad_sch`.
`01-avionics-integration-final.md` §2.2(Teensy 핀맵)·§3(전원계통)을 넷리스트로 옮긴 것. 부품 20개, 넷 30개, 배선 83개.
`.kicad_sch` 전체를 `_tools/gen_schematic.py`가 만든다. 손으로 좌표를 찍은 곳이 없다(이 프로젝트의 "프리핸드 CAD 금지,
코드 기반 파라메트릭 우선" 원칙을 회로도에도 그대로 적용한 것).
같은 폴더의 `cosmos-avionics.kicad_pro`는 생성물이 아니다. KiCad가 저장한 프로젝트 파일을 커밋했고, 생성기는 이 파일을
읽기만 한다. 이 파일이 없으면 생성기가 멈춘다.

**KiCad 10.0.7에서 열고 편집 없이 저장해도 두 파일은 바뀌지 않는다**(#140). 생성기가 결과를 KiCad의
`kicad-cli`로 한 번 더 저장하고, `.kicad_pro`는 KiCad 10.0.7이 쓴 파일을 커밋했기 때문이다. 그래서 파일 머리의
`generator`는 `eeschema`다. 생성물이라는 표시는 제목 칸의 3번 주석(`Generated by kicad/_tools/gen_schematic.py`)에 있다.
KiCad 10.0.6으로 저장하면 `.kicad_pro`가 2줄 바뀐다. 아래 "KiCad 10.0.7로 저장한다" 절을 따른다(#196).

**2026-10-17: ERC(전기 규칙 검사)를 처음으로 실제로 돌렸다**(이민우 PC, KiCad 10.0.6). 결과는 **오류 4개, 경고 129개**다.
리포트는 [`cosmos-avionics/cosmos-avionics-erc.rpt`](cosmos-avionics/cosmos-avionics-erc.rpt)에 있다.
종류별 판정은 아래 "2026-10-17 ERC 결과와 넷 대조 (재생성 전)" 절에 있다.

**⚠️ 이 회로도로 배선하지 않는다.**

같은 날 생성된 회로도를 넷리스트로 뽑아 대조한 결과, 생성기 결함 1건과 §2.2 표 불일치 10행을 찾았다.
`_tools/gen_schematic.py`가 심볼 라이브러리 좌표를 회로도 좌표로 옮길 때 Y축 부호를 바꾸지 않아서, 핀 위치와
레이블이 뒤집혀 있다. 이 결함은 **부품 20개 모두에** 걸린다. 피해 범위는 §2.2 표 10행보다 넓다.

- 짝수 핀 커넥터는 마지막 핀이 연결되지 않는다(ERC 오류 4개·경고 4개가 전부 이것). 홀수 핀 커넥터는 마지막
  핀의 레이블이 1번 핀 자리로 간다.
- **배터리 극성이 반대다.** 넷리스트에서 `/GND`에 `BT1` 1번 핀(`+`)이, `/BATT_RAW`에 2번 핀(`−`)이 들어간다.
- `J5`(Teensy 전원)도 `/+3V3`에 3번 핀(GND 자리)이 들어간다. `Value` 문자열은 `Teensy Power (3V3,VIN,GND)`다.
- `ESC1`의 `+BATT`가 `PhA` 자리, `DSHOT`이 `PhC` 자리로 간다. `U3`(UBEC)은 입력이 GND 자리로 간다.
- `U1`·`U2`(레벨 시프터)의 `+3V3` 레이블은 어떤 핀에도 닿지 않는다. **ERC는 이것을 오류로 세지 않았다.**
- 서보 `S1`–`S4`·수신기 `J7`의 `Value`상 신호인 1번 핀이 `/GND`에 들어간다.

**회로도를 손으로 고치지 않는다.** 고치는 일은 이슈 #66에서 한다. 그때까지 이 파일을 실물 배선의 근거로 쓰지
않는다. 부품별 상세는 아래 "피해 범위 — §2.2 표 10행보다 넓다 (재생성 전)" 절에 있다.

자체 검사 스크립트 두 개 중 `check_imu_nets.py`는 생성기 원본만 보고, `validate_sch.py`의 넷 검사는 레이블
글자 수만 센다. **둘 다 생성된 `.kicad_sch`의 실제 연결을 보지 않는다.** 그래서 둘 다 "일치"로 나왔지만
실제로는 GND 1행이 끊겨 있었다. 자세한 내용은 아래 절에 있다.

## 왜 KiCad를 쓰나

이 프로젝트는 PCB를 새로 설계하지 않는다 — 아비오닉스는 만능기판(perfboard) 수작업 배선이 정본
(`docs/design/01-avionics-integration-final.md` §5). **KiCad는 새 회로를 설계하는 도구가 아니라, 이미
확정된 핀맵·배선을 정식 회로도로 문서화하는 도구**로 쓴다.

- 조립 중 오배선을 조기에 발견하는 대조 도구(전자 탑재 시 스키매틱과 실물 대조).
- 발표·인수인계 자료 — 다음 학기 팀이 마크다운 표 대신 정식 회로도로 배선을 볼 수 있음.
- (스트레치) rev D에서 실제 커스텀 PCB로 갈 경우의 출발점.

## 열어보는 법

1. KiCad 10 설치(무료, [kicad.org](https://www.kicad.org/)) — 이미 이 PC엔 설치돼 있음
   (`%LOCALAPPDATA%\Programs\KiCad\10.0\`). **KiCad 9 이하에서는 회로도가 열리지 않는다.** 파일이
   KiCad 10 형식(형식 번호 `20260306`)이기 때문이다. KiCad 9.0.9는 "KiCad를 10.0 이상으로 올리라"는
   오류 창을 띄운다(#139). 저장할 PC는 **KiCad 10.0.7 이상**을 쓴다. 이유는 아래 "KiCad 10.0.7로 저장한다" 절에 있다.
2. `cosmos-avionics/cosmos-avionics.kicad_pro`를 더블클릭 → KiCad가 열림 → Eeschema(회로도 편집기)
   아이콘 클릭.
3. **회로도를 바꾼 뒤에는 Inspect → Electrical Rules Checker(ERC)를 돌린다.** kicad-cli로도 돌릴 수 있다
   (아래 "2026-10-17 ERC 결과와 넷 대조"). 여기서 나오는 오류·경고를 먼저 확인할 것.
4. 부품 20개가 격자로 나열돼 있음 — 예쁜 배치가 아니라 **넷 연결 확인용 1차 캡처**다. KiCad에서
   재배치한 결과는 커밋하지 않는다. 다시 생성하면 지워지기 때문이다(#140). 배치를 바꾸려면
   `_tools/gen_schematic.py`의 `COMPONENTS` 좌표를 고치고 다시 생성한다.
5. 보기만 하고 저장했으면 `git status`로 확인한다. 두 파일이 바뀌지 않아야 정상이다. KiCad는 같은 폴더에
   `cosmos-avionics.kicad_prl`과 `.history/`도 만든다. 둘 다 `.gitignore`가 무시한다.
6. PCB 편집기를 열어 저장했으면 아래 "PCB를 저장하면 바뀌는 `.kicad_pro`" 절을 따른다.

## KiCad 10.0.7로 저장한다 (#196)

**결론: 회로도나 PCB를 KiCad에서 저장해 커밋할 때는 KiCad 10.0.7 이상을 쓴다.** 커밋된 `.kicad_pro`는
KiCad 10.0.7이 쓴 파일이다. KiCad 10.0.6은 같은 파일을 다르게 쓴다.

- KiCad 10.0.6 회로도 편집기에서 편집 없이 저장하면 `.kicad_sch`는 바뀌지 않는다. `.kicad_pro`는 2줄 바뀐다:
  `"net_colors": {}`와 `"netclass_assignments": {}`가 `null`이 된다(2026-10-19, 서버 Windows VM
  `~/vms/win11-ko`의 KiCad 10.0.6 GUI와 Docker `kicad/kicad:10.0.6` GUI). 두 PC가 쓴 파일은 바이트 단위로 같다.
- 원인은 KiCad 10.0.6의 `common/project/net_settings.cpp`다. 빈 값을 `nlohmann::json ret = {}`(JSON `null`)로
  만든다. 10.0.7은 KiCad 커밋 [5074c82d](https://gitlab.com/kicad/code/kicad/-/commit/5074c82dff7c91588c7ca95f6397690c9a70b581)에서
  `nlohmann::json::object()`(`{}`)로 바꿨다. 서버 KiCad 10.0.7로 다시 저장하면 `{}`로 돌아갔다.
  그래서 두 버전을 섞어 쓰면 저장할 때마다 이 2줄이 오간다.
- PCB를 저장할 때도 다르다. KiCad 10.0.6은 `teardrop_parameters`에 `td_enabled`를 쓰지 않는다(17098 B,
  10.0.7은 17187 B).
- Windows에서 저장한 `.kicad_sch`는 작업 폴더에서 CRLF다. `.gitattributes`(`eol=lf`)가 커밋할 때 LF로
  바꾸므로 `git diff`에는 나오지 않는다. 그런데 KiCad 10.0.6 프로젝트 관리자의 파일 목록은 이 파일 옆에
  빨간 원을 그렸다. KiCad의 git 상태 표시로 보인다. 판단은 `git status`와 `git diff`로 한다.

KiCad 10.0.6 PC에서 저장했으면 커밋하기 전에 둘 중 하나를 한다.

- 보기만 하고 저장했으면 `git restore kicad/cosmos-avionics/cosmos-avionics.kicad_pro`로 되돌린다.
- 일부러 바꾼 설정이 있으면(PCB 설계 규칙 등) 되돌리지 않는다. `git restore`는 그 설정도 지운다.
  KiCad 10.0.7 이상에서 프로젝트를 열고 바꾼 편집기에서 다시 저장한다. 서버 KiCad 10.0.7은 회로도를 다시
  저장할 때 두 `null`을 `{}`로 되돌렸다.

`python tasks.py check`의 `kicadver` 작업은 커밋된 `.kicad_pro`에서 두 값이 `null`이면 실패한다.
KiCad 10.0.8 이후 버전이 이 파일을 어떻게 쓰는지는 아직 확인하지 못했다.

## PCB를 저장하면 바뀌는 `.kicad_pro` (#197)

**규칙: `.kicad_pro`의 PCB 설정은 `.kicad_pcb`와 같은 PR에 커밋한다.** PCB 작업이 아니면 둘 다 되돌린다.
#197의 선택지 (a)다(AI 결정, 차장 위임, 2026-10-19).

### 무엇이 바뀌나 (2026-10-19, 서버 KiCad 10.0.7 GUI)

- 프로젝트 관리자에서 PCB 편집기를 열면 KiCad가 "PCB 파일이 없다. 만들까?"라고 묻는다. 예를 누르고
  Ctrl+S로 저장하면 `cosmos-avionics.kicad_pcb`(2038 B)가 생긴다.
- 같은 저장에서 `.kicad_pro`가 9375 B에서 17187 B가 된다(235줄 추가, 1줄 삭제).
- 바뀐 곳은 `board.design_settings` 하나다. 기본 선 폭과 글자 크기(`defaults`), DRC 규칙(`rules`,
  `rule_severities`), 티어드롭, 길이 맞춤 패턴 같은 PCB 설정이다. 회로도 설정(`schematic`, `erc`)은 바뀌지 않는다.
- KiCad 10.0.7 소스 `pcbnew/board.cpp`는 보드의 설계 설정을 프로젝트 파일의 `board.design_settings`에 둔다.
  그래서 PCB 설계 규칙은 `.kicad_pcb`가 아니라 `.kicad_pro`에 있다. `.kicad_pcb`만 커밋하면 규칙이 빠진다.
- 회로도에는 영향이 없다. 바뀐 `.kicad_pro`로 `gen_schematic.py`를 돌린 결과는 커밋된 `.kicad_sch`와
  바이트 단위로 같다(diff 0줄). PCB를 저장한 뒤 회로도 편집기에서 저장해도 `.kicad_sch`와 `.kicad_pro`는
  바뀌지 않았다. PCB를 한 번 더 저장해도 `.kicad_pro`는 바뀌지 않았다.

### 할 일

1. PCB 작업을 커밋하는 PR은 `cosmos-avionics.kicad_pcb`와 KiCad가 저장한 `cosmos-avionics.kicad_pro`를
   함께 커밋한다. `.kicad_pro`만 먼저 다른 PR로 바꾸지 않는다(선택지 (b)를 고르지 않았다). 두 파일은 함께
   있어야 뜻이 있고, 회로도 재생성에 영향이 없어서 나눌 이유가 없다.
2. 같은 PR에서 `python kicad/_tools/gen_schematic.py`를 다시 돌린다. `.kicad_sch`가 바뀌면 같은 PR에
   커밋한다. KiCad 10.0.7에서는 바뀌지 않았다. PCB도 KiCad 10.0.7 이상으로 저장한다(위 "KiCad 10.0.7로 저장한다" 절).
3. PCB 작업이 아닌데 PCB 편집기에서 저장했으면 `git restore kicad/cosmos-avionics/cosmos-avionics.kicad_pro`로
   되돌리고, 새로 생긴 `cosmos-avionics.kicad_pcb`를 지운다. `git status`에 두 파일이 없으면 끝이다.

`python tasks.py check`의 `kicadver` 작업이 1번을 검사한다. `.kicad_pro`의 `board.design_settings`가 비어
있지 않은데 같은 폴더에 `.kicad_pcb`가 없으면 실패한다. 반대로 `.kicad_pcb`가 있는데 `board.design_settings`가
비어 있어도 실패한다.

이 검사는 작업 폴더의 파일을 본다. git이 파일을 추적하는지는 보지 않는다. 그래서 새 `.kicad_pcb`를
`git add`하지 않아도 로컬 검사는 통과한다. `git commit -a`와 `git add -u`는 새 파일을 넣지 않는다.
커밋된 상태는 CI가 새로 받은 저장소에서 같은 검사로 본다. 커밋하기 전에 `git status`에서 두 파일이 모두
커밋에 들어가는지 확인한다.

## 회로 구성 (`_tools/gen_schematic.py`에 넷리스트 그대로 있음)

### ERC 결과 — 오류 4개, 경고 129개

| 종류 | 개수 | 등급 | 실제 문제인가 | 이유 |
|---|---|---|---|---|
| `pin_not_connected` | 4 | 오류 | **그렇다** | J1 4번, U1 6번, U2 8번, J6 10번이 어떤 배선에도 닿지 않는다. 아래 생성기 결함 때문이다. |
| `unconnected_wire_endpoint` | 4 | 경고 | **그렇다** | 위 4개 핀으로 가야 할 배선 4개가 허공에서 끝난다. 같은 원인이다. |
| `isolated_pin_label` | 2 | 경고 | **그렇다** | `SERVO4_RIGHT` 레이블이 붙은 넷에 핀이 S4 하나뿐이다. J1 쪽 배선이 끊겨 있어서다. |
| `endpoint_off_grid` | 103 | 경고 | 아니다 | 부품 원점이 1.27 mm 격자 밖에 있다(예: y = 25.00). 우리는 PCB를 만들지 않고 문서로만 쓰므로 전기적 문제가 아니다. 다만 소음이 크다. |
| `lib_symbol_issues` | 20 | 경고 | 아니다 | 심볼 라이브러리 `Connector_Generic`·`Device`·`Switch`가 프로젝트 설정에 없다는 경고다. 심볼 정의는 `.kicad_sch` 안에 들어 있어 ERC가 정상으로 읽는다. |

**`J6 Pin 10`의 정체:** `gen_schematic.py`에서 J6 10번은 BNO085의 **GND**다. 그런데 생성된 회로도에서 이 핀은

### 생성기 결함 (이슈 #66)

`_tools/gen_schematic.py`가 심볼 라이브러리 좌표를 회로도 좌표로 그대로 쓴다. 심볼 라이브러리는 Y가 위로

## 재생성 방법 (핀맵이 바뀌면)

`01-avionics-integration-final.md` §2.2·§3이 바뀌면, `_tools/gen_schematic.py`의 `COMPONENTS` 리스트만
고치고 다시 실행하면 된다 — 손으로 `.kicad_sch`를 고치지 않는다(파라메트릭 CAD와 같은 원칙).

```bash
# 어느 PC에서든, 저장소 루트에서 실행한다
python kicad/_tools/gen_schematic.py     # cosmos-avionics.kicad_sch 재생성(kicad-cli로 다시 저장까지)
python kicad/_tools/validate_sch.py      # 구조 자체검증(문법/넷 연결)
```

두 스크립트는 작성자 PC의 절대경로를 쓰지 않는다(10/17 이슈 #67에서 없앴다). 자기 파일 위치를
기준으로 저장소 안의 `.kicad_sch`를 찾는다. KiCad 심볼 라이브러리 폴더는 `--kicad-symbols <폴더>`
인자나 `KICAD_SYMBOL_DIR`(또는 `KICAD10_SYMBOL_DIR`) 환경변수로 주고, 둘 다 없으면 흔한 설치
위치를 훑어 찾는다. 출력 파일 위치는 `--out <파일>`로 바꾼다(기본은 위 `.kicad_sch`).
`validate_sch.py`에 파일 경로를 인자로 주면 그 파일을 검사한다(기본은 같은 회로도).

**생성기는 KiCad 10의 `kicad-cli`가 필요하다**(#140). 생성기는 회로도를 쓴 뒤
`kicad-cli sch upgrade --force`로 KiCad가 저장하는 서식으로 바꾼다. KiCad 10 설치에 들어 있다.
생성기는 심볼 라이브러리 폴더 옆(Windows는 `%LOCALAPPDATA%\Programs\KiCad\10.0\bin\kicad-cli.exe`)과
`PATH`에서 찾는다. 다른 곳에 있으면 `--kicad-cli <파일>`로 준다. KiCad 10이 아닌 `kicad-cli`를 찾으면 멈춘다.
`kicad-cli`가 실패하면 출력 파일을 바꾸지 않고 멈춘다.

- `kicad-cli`는 GUI 저장과 1줄이 다르다. GUI는 파일 끝에 `(embedded_fonts no)`를 쓰고, `kicad-cli sch upgrade`는
  쓰지 않는다. 그래서 생성기가 이 줄을 GUI와 같은 자리에 넣는다. 원인은 KiCad 10.0.7 소스에 있다:
  `sch_io_kicad_sexpr.cpp`는 첫 최상위 시트를 저장할 때만 이 줄을 쓰고, `kicad-cli sch upgrade`는
  파일을 한 번 더 읽어 만든 다른 시트를 저장한다.
- `kicad-cli`는 프로젝트 이름을 `.kicad_pro`에서 읽는다. 그래서 생성기는 커밋된 `.kicad_pro`를 함께 쓴다.
  이 파일이 없으면 멈춘다.
- Windows의 `kicad-cli`는 CRLF로 쓴다. 생성기는 모든 OS에서 LF로 쓴다. 그래서 Windows에서 다시 생성해도
  작업 폴더의 파일이 커밋된 파일과 바이트 단위로 같다(2026-10-19, 서버 VM `~/vms/win11-ko`, KiCad 10.0.6).
- KiCad 10.0.6과 10.0.7로 만든 결과는 바이트 단위로 같다(2026-10-19, 서버 10.0.7과 Docker `kicad/kicad:10.0.6`).

생성기는 **KiCad 10 심볼 라이브러리만** 쓴다(#139). 파일 머리에 KiCad 10 형식 번호를 적고, 심볼 정의는
설치된 라이브러리에서 그대로 복사하기 때문이다. 두 버전이 다르면 KiCad가 파일을 못 열거나 잘못 읽는다.
KiCad 9 라이브러리 폴더를 `--kicad-symbols`로 주면 생성기가 멈춘다. 자동으로 찾을 때는 KiCad 9 폴더를
건너뛴다. `python tasks.py check`의 `kicadver` 작업은 커밋된 `.kicad_sch` 머리가 생성기 값과 같은지,
그리고 `kicad-cli` 단계를 거친 파일인지 본다.
팀이 KiCad 버전을 올리면 `gen_schematic.py` 머리의 버전 상수 4개(`SCH_FILE_VERSION` 등)를 KiCad 소스
`eeschema/sch_file_versions.h`의 값으로 함께 고친 뒤 다시 생성한다.

`_tools/*.py`에 사용자 홈 폴더 경로(Windows `Users`, Linux `home`, macOS `Users` 아래)가 다시 들어오면
`python tasks.py check`가 실패한다. `userpath` 작업이 `파일:줄:칸`을 출력하므로 그 줄을 위 방식
(스크립트 위치 기준 경로, 인자, 환경변수)으로 바꾼다(#96).

**#66을 고치기 전에 다시 생성하면 같은 결함이 있는 파일이 나온다.** 지금 재생성은 "고치는 일"이 아니다.
이 스크립트의 검사는 문법 수준이다 — 괄호 균형, `lib_id` 선언, UUID 중복. **넷 검사는 레이블 글자 수를 세는
것이라 실제 연결을 보지 않는다.** 연결을 확인하려면 `kicad-cli sch export netlist`와 ERC를 돌린다.

`gen_schematic.py`는 UUID를 부품·핀 이름에서 만든다(uuid5, #140). 그래서 같은 입력으로 다시 생성하면
파일이 바이트 단위로 같다. KiCad는 항목을 UUID 순서로 저장하므로, UUID가 실행마다 바뀌면 항목 순서도 바뀐다.

`_tools/extract_symbols.py`는 KiCad 번들 심볼 라이브러리에서 실제 심볼 정의·핀 좌표를 그대로
추출하는 유틸 — 좌표를 손으로 베끼지 않으려고 만든 것(정확성 확보).
