# Stage 2 자유비행 착륙 시뮬레이션

단일 EDF와 베인 4개를 단 강체를 공중에서 놓고 평면 위에 착륙시킨다. PD와 PPO는 같은 환경에서 같은 다섯 명령을 낸다. 시드는 초기 자세와 위치를 정한다. 실물 운용이나 구속 시험대의 Stage 1 성능을 판정하는 데 이 결과를 쓰지 않는다.

## 실행

저장소 루트에서 실행한다. MuJoCo는 `stage2` 선택 의존성이다. 학습 예제의 4,096스텝은 체크포인트 저장과 재평가를 시험할 때 쓰는 예산이다. PPO는 256스텝 단위로 학습한다.

```powershell
python tasks.py stage2
uv run --locked --package cosmos-sim --extra stage2 python -m sim.stage2 evaluate --policy pd --episodes 12 --seed 0 --out sim/runs/stage2/pd
python ship.py capped 8G -- uv run --locked --package cosmos-sim --extra stage2 python -m sim.stage2 train --seed 41 --steps 4096 --model sim/runs/stage2/ppo.zip
uv run --locked --package cosmos-sim --extra stage2 python -m sim.stage2 evaluate --policy ppo --model sim/runs/stage2/ppo.zip --episodes 12 --seed 0 --out sim/runs/stage2/ppo
uv run --locked --package cosmos-sim --extra stage2 python -m sim.stage2 mission --feedback truth --episodes 12 --seed 0 --out sim/runs/stage2/mission
uv run --locked --package cosmos-sim --extra stage2 python -m sim.stage2 mission --feedback estimated --episodes 12 --seed 0 --out sim/runs/stage2/mission
```

`mission`은 아래 §지상 출발 임무를 실행한다.

평가는 한 줄에 에피소드 하나씩 JSON을 출력한다. `outcome`은 종료 원인, `impact_m_s`는 패드가 처음 닿거나 다시 닿을 때 기록한 하강 속도의 최댓값이다. CSV 파일 이름에는 정책과 시드가 들어간다. 같은 출력 폴더에서 같은 정책과 시드를 다시 실행하면 CSV를 덮어쓴다.

웹 뷰어에서 **CSV 열기**로 파일을 골라 **재생**을 누른다. `source=SIM`, `mode=PID`(기준 PD) 또는 `RL`(PPO)이다. 웹은 자세와 서보 명령을 재생한다. `px,py,pz`와 `vx,vy,vz`는 세계 좌표의 CG 위치(m)와 속도(m/s)로 분석용 열이다. 현 뷰어는 이 열로 기체를 이동시키지 않는다. 각 행은 제어 전 상태, 해당 명령과 보상을 담는다. 마지막 행은 종료 상태만 담는다.

## 강체와 힘

[CAD 부품표](../../cad/cg/parts.csv)와 [질량 계산기](../../cad/cg/cg_estimate.py)의 점 질량을 읽는다. 배기면이 CAD 원점이며 +X는 전방, +Y는 왼쪽, +Z는 위다. MuJoCo의 강체 원점을 CG에 두고 CAD의 모든 힘 작용점과 충돌 형상에서 CG를 뺀다. 비대각 성분까지 계산한 CG 기준 관성 텐서를 넘긴다. [설계 03 §2·§4](../../docs/design/03-control-pipeline-design.md)

PyFlyt의 양력면은 링크의 속도에서 바람을 뺀다. 기본 모델에는 정지 호버 중에도 베인에 작용하는 제트 속도가 없다. PyFlyt 0.29는 NumPy <2를 요구하고 저장소는 2.5.3을 고정한다. 여기서는 헤드리스 MuJoCo가 6자유도 운동과 충돌을 적분하고 자체 제트 모델이 외력을 공급한다. [저장소 조사 §3](../../docs/design/rl-open-source-survey.md) · [PyFlyt 소스](https://github.com/jjshoots/PyFlyt/blob/master/PyFlyt/core/abstractions/lifting_surfaces.py) · [배포 의존성](https://pypi.org/pypi/PyFlyt/0.29.0/json) · [MuJoCo 관성 정의](https://mujoco.readthedocs.io/en/stable/XMLreference.html#body-inertial)

EDF 추력 T를 원주 방향으로 4등분한다. 한 베인의 측력은 `T × CLalpha × A_fin / (2 × A_duct) × angle_rad`이다. 절댓값의 상한은 `(T/4) × sin(10°)`다. 명령 한계 ±10°에서 측력은 최대 0.0311·T라 이 상한(0.0434·T)에 닿지 않는다. 상한은 상수를 바꿀 때의 안전장치다. 각 구간의 축력은 `sqrt((T/4)² − 측력²)`이다. 작용점마다 힘과 CG 기준 모멘트 `r × F`를 합산한 뒤 세계 좌표로 회전한다. 양의 명령에서 1·3번 측력은 +Y, 2·4번은 +X다. 서보의 실물 장착 부호는 별도 보정 대상이다.

## 관측과 착륙 판정

정책은 세계 좌표 위치·속도 6개, 기체에서 세계로 회전하는 쿼터니언(wxyz) 4개, 기체 각속도(rad/s) 3개, 현재 베인각(rad) 4개, EDF 속도 비율 1개를 받는다. 설계 03에 열거한 값은 17개다. 여기에 지연된 EDF 상태를 더해 총 18개다. 행동은 FWD/LEFT/AFT/RIGHT 베인 명령과 스로틀이다. 각 행동 범위는 −1에서 +1이고 스로틀만 0에서 1로 환산한다.

물리 적분은 4 ms마다 하고 제어는 20 ms마다 한다. 초기 발 높이는 수평 자세 기준 0.45–0.65 m, CG의 수평 위치는 축마다 ±0.05 m, 초기 자세각은 축마다 ±0.055 rad 범위에서 뽑는다. 초기 속도는 0이며 EDF 초기 회전 비율은 수평 호버 추력에 맞춘다. PD는 수평 위치와 속도로 목표 기울기를 정하고 하강 속도와 자세 오차를 추력·토크로 환산한다. 착지 높이 3 mm 안에서 스로틀을 끈다.

- 패드가 새로 닿을 때 패드 중심의 하강 속도가 0.45 m/s 또는 수평 속도가 0.40 m/s를 넘으면 강한 접촉으로 종료한다.
- 패드 3개 이상이 닿고 EDF 속도 비율이 0.10 이하인 상태에서 착륙을 판정한다. 수평거리 0.20 m 미만, 기울기 8° 미만, 속력 0.10 m/s 미만, 각속력 0.25 rad/s 미만을 포함한 모든 조건이 연속 0.15 s 유지돼야 한다.
- 하우징 접촉, 45° 초과 기울기, 수평거리 1.5 m 또는 CG 높이 2.5 m 초과는 실패로 종료한다. 8 s가 지나면 시간 제한으로 중단한다.
- 매 제어 스텝에 경과 시간, 남은 높이, 수평 오차, 기울기와 속도에 비용을 준다. 착륙 보상은 +10, 실패는 −10, 시간 초과는 −5다. 모든 문턱은 이 시나리오의 비교 조건이다.

## PPO 착륙률 (#296)

[ppo_budget.py](ppo_budget.py)는 PPO를 학습 예산별로 저장하고, PD와 같은 평가 seed로 종료 원인을 센다. **2026-11-18 결과: 세 조건 모두 1M 스텝까지 착륙 0/100이다. PD는 100/100이다.**

```powershell
python ship.py capped 6G -- uv run --locked --package cosmos-sim --extra stage2 python -m sim.stage2.ppo_budget train --condition vecnorm --reward env --envs 4 --threads 1 --budgets 250000 500000 1000000 --out sim/runs/stage2/296
uv run --locked --package cosmos-sim --extra stage2 python -m sim.stage2.ppo_budget evaluate sim/stage2/checkpoints/ppo-vecnorm-s41-1000000.zip
```

- 학습 seed: `make_vec_env(seed=41)`이 환경 4개에 seed 41-44를 준다. 평가 seed는 1000-1099다. 두 범위가 겹치면 `train`이 멈춘다.
- PPO: SB3 기본값에서 `n_steps=512`, `batch_size=256`만 바꿨다. 환경 4개, 1M 스텝에 서버에서 약 30-33분 걸렸다(다른 학습과 함께 돌렸다).
- 조건: `raw`(원시 관측), `vecnorm`(관측·보상 VecNormalize), `vecnorm` + `timeout10`(학습 래퍼가 시간 초과 벌점을 −5에서 −10으로 바꾼다. 환경은 그대로다).
- 1M 체크포인트는 [checkpoints/](checkpoints/)에 있다. `vecnorm` 조건은 같은 이름의 `.vecnormalize.pkl`을 함께 읽는다.

평가 seed 1000-1099, 100회:

| 정책 | 250k | 500k | 1M | 1M 종료 상태(seed 1000-1019) |
|---|---|---|---|---|
| PD | 착륙 100 | | | 착륙 하강 속도 최대 0.304 m/s |
| `raw` | 시간 초과 97, 이탈 3 | 시간 초과 100 | 시간 초과 100 | 높이 0.88-0.96 m에서 계속 오른다 |
| `vecnorm` | 시간 초과 100 | 시간 초과 100 | 시간 초과 100 | 높이 0.29-0.33 m, 수평 0.43-0.47 m에서 떠 있다 |
| `vecnorm` + `timeout10` | 시간 초과 100 | 시간 초과 100 | 시간 초과 100 | 높이 0.40-0.69 m, 수평 0.00-0.10 m에서 떠 있다 |

- 확인한 사실: 세 조건 모두 강한 접촉, 기울기 초과, 하우징 접촉이 0이다. 정책은 넘어지지 않고 떠 있다. 바닥에 내려가지 않는다.
- 확인한 사실: 착륙 판정은 EDF 속도 비율 0.10 이하를 요구한다. 바닥에 닿은 채 스로틀을 0.10보다 높게 유지하면 `time_limit`가 된다. 이번 1M 정책들은 seed 1000-1019에서 바닥 위 0.29-0.96 m에 떠서 끝났다. 그래서 이 조건이 결과를 바꾸지 않았다. 나머지 seed의 종료 높이는 재지 않았다.
- 추론: 착륙 판정은 패드 3개 접촉, EDF 속도 비율 0.10 이하, 정지 상태를 0.15 s 유지해야 한다. 무작위 탐색으로 이 상태에 닿기 어려워서, 정책이 떠 있는 국소해에 머문 것으로 보인다. 시간 초과 벌점을 키워도 1M 안에서는 바뀌지 않았다.
- 한계: 학습 seed는 41 하나다. 1M보다 큰 예산, 보상 모양 바꾸기(접지 접근 보상), 커리큘럼(낮은 높이에서 시작), PD 잔차 학습은 시험하지 않았다. 후속 이슈 #413에서 다룬다.

## 지상 출발 임무

[mission.py](mission.py)는 발 패드가 바닥에 닿고 EDF가 멈춘 상태에서 시작한다(`reset(options={"start": "ground"})`). 기체는 아래 구간을 이어서 실행하고 착지점 (0.50, 0) m에 내린다. 착륙 판정은 §관측과 착륙 판정과 같다. 다만 기준점이 착지점이고, 패드가 바닥에서 한 번 떨어진 뒤에만 착륙을 센다.

| 구간 | 시간 | 기준 궤적 |
|---|---|---|
| `takeoff` | 3 s | 휴지 높이에서 0.50 m 위로 오른다 |
| `hover1` | 2 s | 그 높이를 유지한다 |
| `translate` | 3 s | 시작 위치에서 착지점 위로 수평 이동한다 |
| `hover2` | 2 s | 착지점 위를 유지한다 |
| `land` | 4 s | 휴지 높이보다 30 mm 아래까지 내린다. 높이 3 mm 안에서 스로틀을 끈다 |

- 모든 구간은 최소 저크 5차 곡선이다. 구간 끝의 속도와 가속도는 0이다.
- 기준 궤적의 최대 속력은 0.3125 m/s, 최대 가속도는 0.321 m/s²다. 검사 상한은 0.40 m/s(강한 접촉의 수평 속도)와 1.0 m/s²(PD의 수평 가속도 제한)이다. 수평 가속도 제한이 만드는 최대 기울기 명령은 8.2°다.
- `TrackingPD`는 `LandingPD`의 자세·배분 루프를 쓰고, 위치·속도 기준을 추종한다. 적분항은 없다.
- 결과 JSON에는 구간별 위치·속도 오차(RMS, 최대), 추정 위치 오차, 착지 위치 오차, 최대 기울기, 추력·베인 포화 비율, 센서 유효 비율이 있다.
- CSV에는 웹 열 뒤에 `phase`, `ref_px..ref_pz`(기준 궤적), `est_px..est_pz`(제어기가 쓴 위치)를 더한다. 웹 뷰어는 헤더 이름으로 열을 읽으므로 이 열을 무시한다. 검사는 `web/src/csv.js`의 `REQUIRED`·`NUMERIC` 열이 모두 있는지, `phi,theta,psi`가 같은 행 쿼터니언의 ZYX 오일러 각인지, `pz`가 바닥(z=0) 위 CG 높이인지 본다.

### 참상태 피드백과 추정 피드백

`--feedback truth`는 시뮬레이터의 위치·속도·자세·각속도를 그대로 쓴다. 실기에는 이 입력이 없다. `--feedback estimated`는 아래 센서를 가정하고 그 출력만으로 상태를 만든다. **모든 센서 값은 비교용 가정이다. 데이터시트나 실측값이 아니다.**

| 입력 | 가정한 센서 모델 | 한계 |
|---|---|---|
| 자세 | IMU 융합 자세. 롤·피치 오차는 에피소드마다 ±0.5° 안의 상수, 요 오차는 0.2°/√s 랜덤 워크 | 롤·피치 오차가 적분 없는 위치 루프에 정상 위치 오차를 남긴다. 0.5°이면 약 g·sin0.5°/2 = 4.3 cm다 |
| 각속도 | 자이로. 바이어스 ±0.01 rad/s, 잡음 σ 0.005 rad/s | 바이어스가 광류 보정에 남는다 |
| 높이 | 하향 거리 센서. CAD (60, 0, 0) mm(배기면)에서 기체 −Z로 잰다. 범위 0.04-4 m, 잡음 σ 5 mm. 추정 자세로 기울기를 보정하고 α-β 필터로 높이·수직 속도를 구한다 | 바닥에서도 센서가 148 mm 위에 있어 범위 안이다. 거리 센서 위치(배기 흐름 간섭)는 확인하지 않았다 |
| 수평 속도 | 광류. 기체 수평 속도에 잡음(σ 0.03 rad/s × 거리)과 자이로 오차 × 거리를 더한다. 거리 0.08 m 미만이면 쓰지 않는다 | 광류 센서의 초점·조도·바닥 무늬 조건은 모델에 없다 |
| 수평 위치 | 광류 속도의 적분 | 절대 위치 기준이 없어서 시간이 지날수록 오차가 커진다 |

|---|---|---|

## 검증 범위

`python tasks.py check`에는 CG·관성 변환, 네 베인의 측력과 요 부호, 무추력 자유낙하, 기울어진 기체의 병진 가속도, 시드 재현, 연착륙·강한 접촉·시간 초과와 CSV 검사도 들어 있다. 지상 출발 임무는 기준 궤적 제한, 지상 출발을 착륙으로 세지 않는지, 두 피드백의 seed 0-1 착륙, 웹 CSV 좌표 기준을 검사한다. PD와 PPO는 같은 초기 시드를 사용할 수 있다. 시드는 기체 물성치를 바꾸지 않는다.

실측 전 항목은 실험 A(#244), 조립 질량·CG·관성(#261, #262), 베인 치수·제트 단면·복원 모멘트(#265, #118, #263), 서보와 EDF 응답(#202, #264), 접촉 모델(#295)이다. 공기 저항·돌풍, 회전자 반작용과 자이로(#119), 지면 효과, 배터리 전압 강하, 구조 변형은 모델에 없다. 센서 오차는 `mission --feedback estimated`의 가정 모델에만 있다. 착륙 환경과 `--feedback truth`에서 초기 위치와 속도, 베인각은 시뮬레이터의 참값이다. 실기 탑재에는 별도 관측기와 구속 시험이 필요하다.
