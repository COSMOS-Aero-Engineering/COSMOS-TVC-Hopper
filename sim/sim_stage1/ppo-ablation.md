# 스로틀 0 지름길을 막은 뒤 PPO 학습 조건 비교 (#230, #344)

## 결론

스로틀을 100 %로 고정하고 1M 스텝 학습하면 PPO가 PD보다 낫다. 조건을 하나씩 더 바꾼 것 중에는 종료 비용(`crashcost`)이 가장 좋았다. 학습 seed 3개 평균 리턴 -1.93, 넘어짐 0 %, 최종 기울기 중앙값 0.7°다. PD는 -4.82, 0 %, 2.5°다.

- 200k 스텝에서는 고정 스로틀만으로 부족하다. 평가 seed의 93.7 %가 넘어진다. 학습 곡선은 약 250k 스텝 뒤에 넘어짐에서 벗어난다.
- 종료 비용을 더하면 이 시점이 빨라진다. 200k에서 학습 seed 3개 중 2개가 PD보다 낫다. 종료 비용과 3축 믹서를 같이 쓰면 3개 모두 넘어짐 0 %다.
- 1M 스텝에서는 네 조건(`fixed`, `mixer`, `vecnorm`, `crashcost`)이 모두 PD보다 낫다. 차이는 리턴 0.3 이하다.
- 2차 조합 `crashcost_mixer`, `crashcost_vecnorm`도 1M에서 PD보다 낫다(-2.53, -2.04). 둘 다 `crashcost` 1M(-1.93)보다 좋지 않다(#344).
- 저장소에 둔 모델은 `hopper_attitude_ppo_230.zip`(`crashcost`, 1M, 학습 seed 10001)이다.

Stage 1 결과다. 물리 상수는 실험 A 전 임시값이다. 실기 성능으로 해석하지 않는다.

## 조건

모든 조건은 SB3 PPO 기본 하이퍼파라미터(`gamma` 0.99)를 쓴다. 각 조건은 기준 조건에서 한 가지만 바꾼다. 정의는 `ppo_ablation.py` 머리 설명과 `policy_io.py`에 있다.

| 조건 | 기준 | 바꾼 것 |
|---|---|---|
| `learned` | - | #230 전 `train.py`. 정책이 베인 4개와 스로틀을 낸다 |
| `fixed` | `learned` | 스로틀 100 % 고정. 정책은 베인 4개만 낸다 |
| `mixer` | `fixed` | 롤·피치·요 3축 믹서 행동 |
| `vecnorm` | `fixed` | 관측만 `VecNormalize`로 정규화 |
| `crashcost` | `fixed` | 넘어질 때 종료 비용 |
| `crashcost_mixer` | `crashcost` | 3축 믹서 행동 |
| `crashcost_vecnorm` | `crashcost` | 관측만 `VecNormalize`로 정규화 |

종료 비용: 넘어진 스텝의 보상 r에 r·γ·(1 - γ^n)/(1 - γ)를 더한다. n은 남은 스텝 수다. 넘어진 상태로 에피소드 끝까지 머문 할인 리턴과 같다. 학습에서만 쓴다. 평가 리턴은 환경 보상 그대로다. 고정 길이 평가 대신 이 방법을 골랐다. 60°를 넘은 뒤 적분을 계속하면 오일러각 특이점(θ = 90°)에 가까워지기 때문이다.

### 정상오차 0.64°의 출처 (#357)

**결론:** 0.64°는 기체의 무게중심 오프셋에서 나온다. 무게중심이 추력축에서 벗어나면 추력에 비례하는 토크가 늘 생긴다. 정책은 이 토크를 베인으로 상쇄하는데, 관측에 오프셋도 적분 상태도 없다. 그래서 필요한 베인 명령을 기울기에서 만들고, 오프셋에 비례하는 기울기에서 멈춘다. 평가 seed k의 기체는 초기 자세 조건과 상관없이 같으므로 평균도 0.64°로 같다.

```bash
python ship.py capped 8G -- uv run --frozen --project . python sim/sim_stage1/steady_error_check.py
```

평가 seed 0-199. 서버(Linux)에서 6분 21초 걸렸다. 표는 출력에서 열 일부만 옮겼다. "무게중심 0"은 `reset()` 뒤 `cg_offset_x`·`cg_offset_y`만 0으로 바꾼 조건이고, "랜덤화 끔"은 모든 상수가 명목값인 조건이다. 환경 코드와 `params.yaml`은 바꾸지 않았다.

- **무게중심 오프셋:** 오프셋만 0으로 두면 PPO 정상오차가 0.638°에서 0.061°로 줄어든다. 관성·팔 길이·Kf 랜덤화를 함께 꺼도 0.061°다. 남은 0.061°는 거의 피치다. 수평·정지 관측에서 정책 출력이 0이 아니다(a1-a4 = 0.007, 0.079, -0.020, 0.075). 이 치우침이 피치 0.06°를 만드는 것으로 보인다.
- **롤·피치:** 롤 0.544°, 피치 0.244°로 롤이 크다. 마지막 구간 평균 롤은 `cg_y`에, 피치는 `cg_x`에 직선으로 맞는다(상관 r 0.9985, -0.9999). 무게중심 1 mm당 롤 0.382°, 피치 0.176°다. 정책의 피치 강성이 롤보다 약 2.2배 크다.
- **초기 기울기:** seed별 정상오차는 학습 분포와 기울기 10° 조건에서 최대 0.0012°, 40° 조건에서 최대 0.0107° 다르다. 초기 자세는 정상오차를 정하지 않는다.
- **PD와 같은 원리:** PD도 무게중심 0이면 정상오차가 0이다. 1 mm당 1.108°는 손계산 1/(kp·2·CL·alpha_max·l) = 1/(8 · 6.466 mm) rad와 같다. PPO는 같은 오프셋에서 PD보다 롤 약 2.9배, 피치 약 6.3배 덜 기운다.
- **포화·진동·요가 원인이 아니다:** 마지막 구간 베인 명령 크기는 최대 0.522이고 포화(|a| ≥ 0.999)는 0 %다. 구간 안 기울기 표준편차는 최대 0.0055°라 진동이 아니라 정지 평형이다. 요는 기울기 hypot(phi, theta)에 들어가지 않는다.
- **보상 항:** 마지막 구간 스텝당 자세 비용은 PPO 2.24e-04, PD 8.54e-03이다. 행동 비용은 둘 다 1.26e-03이다. 오프셋을 상쇄하는 베인 명령은 두 정책이 같아야 하므로 행동 비용도 같다. 행동 비용 0.001·Σa²이 기울기를 남기게 한 것인지는 확인하지 못했다(재학습 필요, 이 이슈 제외).

발표에서는 "PPO 정상오차 0.64°는 무게중심 오프셋 ±3 mm 랜덤화에서 나온다. 적분이 없는 정책이 오프셋 토크를 기울기로 버틴다"로 설명할 수 있다. 실물의 무게중심 오프셋은 아직 재지 않았다(01 문서 §8.2 목표 ≤ 3 mm).

python ../../ship.py capped 8G -- python ppo_ablation.py train --condition crashcost --seed 1 --steps 1000000
# 조건 하나 x 학습 seed k (결과: runs/230/<조건>_<스텝>k/seed<k>/)

같은 커밋에서 `crashcost` 200k 학습 seed 0을 다시 학습하면 정책 가중치(`policy.pth`)의 SHA-256이 같았다. `result.json`도 학습 시간 외에는 같았다. zip 파일 자체는 저장 시각 때문에 다르다.
